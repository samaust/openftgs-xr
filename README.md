# openftgs-xr

An Apache-2.0 Rust workspace that implements a player for openftgs models generated by [openftgs](https://github.com/samaust/openftgs), built twice from one codebase on [Bevy](https://bevy.org/) and OpenXR: a Linux desktop player with keyboard and mouse, and a Meta Quest 3 OpenXR app with controllers, hand tracking and passthrough.

## Status

The specification, `docs/spec/openftgs-xr-spec.md`, is at revision 63 (2026-11-15); `docs/spec/README.md` records its revisions. Seven of the nine milestones in `docs/prd/milestones.md` are done: M-1 core and I/O, M-2 the desktop renderer and the headless commands, M-3 the XR spike, M-4 the desktop application, M-5 XR interaction, M-6 passthrough and environment, and M-7 light estimation and color matching. M-8, performance, is in progress ([#718](https://github.com/samaust/openftgs-xr/issues/718)). M-9, polish and release, has not started.

Both builds work:

- **Desktop.** `cargo run --release --bin ftgsxr -- play [MODEL|URL|SCENE ...]` opens the player. The same binary has the headless commands `render`, `info`, `validate`, `import`, `export` and `bench` (spec §1.7). The build needs ALSA's development package (spec §2.3).
- **Quest 3.** `tools/build-quest.sh [debug|release]` builds the APK with cargo-ndk and Gradle (spec §2.5) and prints its path. The script's header lists what it needs.

Plain `cargo test` runs the `cpu` lane. The tests that need a GPU, an OpenXR runtime, the headset, the network or the datasets are in their own lanes (`crates/README.md`).

What is still open:

- **The headset's frame time.** The Quest 3 misses P-1's 12.4 ms GPU budget per frame in `quest-balanced`, even with occlusion off ([#801](https://github.com/samaust/openftgs-xr/issues/801), [#802](https://github.com/samaust/openftgs-xr/issues/802)). Its sort also misses P-4's 2.5 ms ([#123](https://github.com/samaust/openftgs-xr/issues/123)). Two PRDs are planned to close the gap: the sort experiments ([#829](https://github.com/samaust/openftgs-xr/issues/829)) and foveation on the splat layer ([#804](https://github.com/samaust/openftgs-xr/issues/804)).
- **M-9.** Still to do: drawing the HUD overlay and the per-instance overlays, the library's thumbnails, the licenses on the Help tab, the panel's Controls page, release packaging and signing, and the documentation.

## Languages

Rust for all application code and WGSL for shaders; a minimal Kotlin or Java shim on Android only where an Android API has no native path; Python only in dev tooling (the agent skills' scripts and the fixture generation that drives openftgs). The rule and its date are in `CLAUDE.md`.

## Relation to openftgs

openftgs trains the models; openftgs-xr only loads and displays them. `docs/spec/openftgs-spec.md` is a copy of the openftgs spec, kept as the reference for the files openftgs-xr reads. The openftgs-xr spec, `docs/spec/openftgs-xr-spec.md`, is this package's own.

## Repository layout

- `crates/`: the workspace's eight crates (spec §2.1), each with its spec tests in `tests/`. `crates/README.md` says where the tests live and which lane each runs in.
  - `ftgsxr-core`: the model and its loaders, the CPU mathematics, the clock, the GPU layout and the openftgs formats.
  - `ftgsxr-io`: paths, settings, scene and pose files, listings, HTTP and model sources.
  - `ftgsxr-render`: the wgpu render layer and its Bevy plugin.
  - `ftgsxr-xr`: the OpenXR session, tracking, passthrough, depth, light, anchors and the panel.
  - `ftgsxr-app`: everything the desktop and Quest builds share.
  - `ftgsxr-desktop`: the Linux player and command line, the binary `ftgsxr`.
  - `ftgsxr-quest`: the Meta Quest 3 entry point, the library `libftgsxr_quest.so`.
  - `ftgsxr-testkit`: fixtures, checksums, image metrics and synthetic models for the tests.
- `android/`: the Gradle project that packages the Quest APK, with the manifest, the activity and the Kotlin shim (spec §2.5).
- `vendor/`: patched copies of bevy\_mod\_openxr, bevy\_render, wgpu-core and wgpu-hal, each under its own license, applied through the workspace `Cargo.toml`'s `[patch.crates-io]`, whose comments name the decision behind each patch (D-30, D-52, D-53, Q-139).
- `tools/`: `build-quest.sh`, which builds the APK, and `fixtures/`, the Python scripts that generate the test fixtures and `train_tiny.sh`, which drives openftgs to train the tiny models (spec §2.7).
- `tests/fixtures/`: the generated fixtures with their `SHA256SUMS`, shared by every crate's tests.
- `benchmarks/baselines/`: the stored `ftgsxr bench` results that regression runs compare against (spec §3.5).
- `deny.toml`: cargo-deny's license and advisory scan (spec §2.3, §2.6).
- `.github/workflows/`: CI, which runs formatting, clippy, cargo-deny and the `cpu` lane on every push, and the GitHub Pages site that serves the `net` lane's test index.
- `docs/spec/`: the openftgs-xr spec, the copy of the openftgs spec, and the record of spec revisions.
- `docs/prd/`: the milestones, the implementation questions and their provisional decisions, and the source log.
- `docs/GLOSSARY.md`: the project's vocabulary.
- `docs/modules/`: documentation of the crates' modules, one directory per crate.
- `docs/agents/`: how the agent skills use the issue tracker, its labels, the guidelines and the domain docs.
- `.claude/skills/`: the agent workflow, from planning to implementation and review.

## Environment variables

None is needed to build the desktop player or run plain `cargo test`.

The desktop player:

| Variable | What it sets |
| --- | --- |
| `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME` | Where the settings, pose store and scenes, the HTTP cache and logs, and the default model directory go, each under `openftgs-xr/` (spec §1.11, D-23). Default `~/.config`, `~/.cache` and `~/.local/share`. |
| `XDG_PICTURES_DIR` | Where screenshots go, under `openftgs-xr/`. An absolute path is used as is; otherwise the user-dirs file's entry, else `~/Pictures` (Q-14). |
| `XR_RUNTIME_JSON` | The OpenXR runtime `play --xr` uses, read by the OpenXR loader; unset, the system's active runtime. |
| `FTGSXR_BENCH_BASELINES` | The directory of the baselines `ftgsxr bench` compares against. Default the workspace's `benchmarks/baselines/` (Q-103). |

Building the Quest APK with `tools/build-quest.sh`:

| Variable | What it sets |
| --- | --- |
| `ANDROID_HOME` | The Android SDK. Default `~/Android/Sdk`. |
| `ANDROID_NDK_HOME` | The NDK. Default `$ANDROID_HOME/ndk/25.1.8937393`. |
| `GRADLE_ARGS` | Extra arguments for Gradle, such as `--max-workers=8`. |
| `CARGO_BUILD_JOBS` | Cargo's parallel jobs, as for any cargo build. |

The test lanes other than `cpu` (`crates/README.md`):

| Variable | Lane | What it sets |
| --- | --- | --- |
| `OPENFTGS_DATASETS` | `ds` | The datasets directory, whose `xr-fixtures/` holds the models `tools/fixtures/train_tiny.sh` trains. Required. |
| `FTGSXR_NET_INDEX` | `net` | The base URL of the public HTTPS index I-21 lists, which the Pages workflow publishes (Q-156). Required. |
| `XDG_RUNTIME_DIR` | `xr` | Where Monado's socket is found. The `xr` tests select Monado through `XR_RUNTIME_JSON` themselves. |
| `FTGSXR_QUEST_APK` | `dv` | The debug APK to install, built by `tools/build-quest.sh debug`. Required. |
| `ANDROID_HOME` | `dv` | Where `adb` (when not on the `PATH`) and `aapt2` are found. |
| `ANDROID_SERIAL` | `dv` | The headset, when `adb devices` lists more than one device. |
| `FTGSXR_DV_OUT` | `dv` | A directory that keeps a copy of each file the tests pull from the headset. |
| `FTGSXR_DV_TREE` | `dv` | The URI of the document tree granted through the app's picker, which Dv-10 reads (Q-273). |
| `FTGSXR_R17_ROWS`, `FTGSXR_SPIKES_ROWS` | `dv` | The row count of a heavier model than the default for R-17's headset run and for the spike runs (Q-420). |
| `FTGSXR_WATCHDOG` | `gpu` | Set to `1` to check R-6's 1 ms bounds rather than only report them, on a machine running nothing else (Q-111). |
| `FTGSXR_RECORD_R12_EXACT`, `FTGSXR_RECORD_Q448_EXACT`, `FTGSXR_RECORD_Q450_SCALED` | `gpu` | Set to record the reference layers of the exactness checks instead of comparing against them, only in a commit of its own before an exact change (Q-445). |

The fixture tools in `tools/fixtures/` (spec §2.7):

| Variable | What it sets |
| --- | --- |
| `OPENFTGS_REPO` | The openftgs clone. `train_tiny.sh` requires it and runs its `.venv`; the Python scripts run under that `.venv`'s Python and record the clone's commit. |
| `OPENFTGS_DATASETS` | The datasets directory, as above; `train_tiny.sh` requires it and reads the openftgs-synth dataset in `synth/`. |
| `XR_FIXTURES` | Where `train_tiny.sh` writes the trained models. Default `$OPENFTGS_DATASETS/xr-fixtures`. |
| `THREADS` | The CPU threads of every `train_tiny.sh` command. Default 3. |
| `FIXTURES_THREADS` | The CPU threads of every openftgs run of the Python scripts, so reruns match bit for bit. Default 6 (Q-415). |
| `FIXTURES_WORK` | The scripts' intermediates, never committed. Default `.scratch/fixtures-work`. |
