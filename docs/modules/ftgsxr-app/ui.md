# The interface in `ftgsxr-app`

How `ftgsxr_app::ui` meets the panels (§1.7 Panels, D-21, §1.8 User interface), the toasts (§1.13 Logs, §1.15), the HUD's data (§1.13 HUD) and the ray-to-pointer mapping (§1.8, I-11, U-32), with `ftgsxr_app::capture`'s screenshots (§1.7 Screenshots), and panel mode on the headset (§1.8 User interface, D-21). The spec items are those and §2.1's `ftgsxr_app::ui` and `ftgsxr_app::capture`; this doc explains them and never overrides them. Built in M-4 (#286, #287 and the #286 follow-up); panel mode and the wrist menu's buttons in M-5 (#453, #456).

## Dependency direction

`ui` comes before `audio`, `persist`, `governor` and `desktop_input` in §2.1's order, so it names none of their types (PRD #275's "Dependency direction"). Instead the later modules use ui's crate-private seams:

- **`ToastRequest`**: every module asks for a toast through it; ui's limiter turns it into the `Toast` message (Q-208). Library, playback, audio and persist failures arrive this way (Q-173, Q-217, Q-189, Q-201); the XR crate, outside the app crate, triggers a `Toast` as an observer event, which ui turns into a `ToastRequest` (Q-221).
- **`UiCue`**: what ui wants heard; `audio` maps it to its UI sounds.
- **`SceneLoadConfirmed`**: the confirmed scene load, which `persist` turns into `PersistCommand::LoadScene` (Q-200).
- **`DockHooks`**: later modules add their own sections to the dock's tabs (Q-218): persist's display, environment, settings and Comfort sections, audio's volumes, governor's tier and switch, desktop_input's Help shortcuts. A section added with `add_screen_only` is drawn on the screen only, never on the main panel (Q-294).

The XR crate, outside the app crate and above it, reaches `ui` through public items: it writes `PanelPointer` for a ray on a panel quad (Q-263) and sets `UiSurface::Panel` when it spawns the main panel (`ftgsxr-xr/panel.md`).

## Structure

What runs without egui (the toasts and their limit, the confirmations, the UI commands, `HudData`, the `PanelPointer` message) is added in every app; the drawing and the panel pointer only when `EguiPlugin` is, which `AppPlugin` adds only when the render app exists (PRD #275's spike check 1 and its fallback).

- **The screen.** Drawn only while a primary window exists. `ui/dock.rs` draws the bar above the viewport, the dock on the left with its seven tabs (resizable between 160 points and 60 % of the window, §1.7 Panels and Q-251; `persist` saves the width the user dragged it to and whether it is open; a window too narrow for that width clamps only the drawing, Q-252), the toast line and the confirmation dialogs in one exclusive system, which collects what the user did and sends it after the frame. egui draws no text without a font: the desktop loads the first readable system font of a fixed list at startup (Q-211).
- **Toasts.** The rate limit keys on a toast's text: one toast of the same text a second, a later one within the second dropped; a toast stays on the line for a few seconds, the newest few shown (Q-208). The capacity overflow has its own warning text, naming the capacity only, so it is the same each frame and a per-frame overflow shows once a second (Q-209). An unavailable XR feature gives a toast only when it was explicitly asked for, at most once per session per extension (Q-161).
- **Instance color.** The Scene tab edits each instance's E14 manual form (exposure in EV, temperature and tint) as `InstanceLighting`, and sets its `SplatTransform` to `ColorTransform::from_manual` of that form, E14's manual form computed once in `ftgsxr-render` for both builds (Q-218, Q-250). `persist` saves and restores it as the scene's `lighting`.
- **Confirmations.** Delete's `UnloadRequest` (Q-199) and `Intent::Ui(LoadScene)` (Q-200) open a dialog; only a confirmation sends the unload or the load. A missing entry's "Replace with…" (§1.5 Library) opens the files picker; the first picked file opens the dialog "Replace <model> with <path or URL>?", and only yes sends `library`'s `ReplaceEntry` (Q-255, Q-256, Q-257).
- **HUD.** `HudData` holds Q-159's fields, filled each frame from `SplatStats`, the clock, the instances and the tier state, and Q-274's `head_tracked`, which the XR crate writes (`ftgsxr-xr/tracking.md`). Q-274's two hand fields are not built: they wait for the owner's answer, since their `HandSource` lives in `ftgsxr-xr`, which this crate cannot name.
- **The world panel.** `panel_hit` maps a ray to a pixel of a `WorldPanel` quad, front side only, the top-left corner pixel (0, 0) (Q-210); the XR crate's ray test uses it.
- **Training cameras and requests.** `ui/cameras.rs` offers in the Scene tab the cameras of a manifest beside a model, or of the one an HTTP index entry names, which `library` downloads with the model (#374): the list by split, "jump to camera", the frustums in the instance's frame. It also replays a `ftgs-render-request` file found in a directory source from the Library tab. A jump moves the fly camera through `rig`'s `CameraJump` and seeks the clock to the image's timestamp (E9, Q-219). Cameras follow openftgs's conventions (E6, §1.14 Frames). While a request replay is open (from Open to Close or its replacement), `follow_replay` makes the request's background `rig`'s `BackgroundOverride` and its `sh_degree` the render plugin's `SplatShLimit`, and clears both without one; neither the governor's `SplatTierState` nor the settings are written, so Close restores the player's own (Q-233, Q-234, Q-235). `rig`'s view following draws `DesktopView`'s background, or the override, on every splat camera that draws a background, each frame, so the XR eyes follow it too; a camera that draws none (passthrough) is left alone.

## Panel mode

On the headset, the `Headset` marker (Q-266), the interface draws on the quads' textures instead of the window (`ui/panel.rs`, §1.8 User interface, D-21). `play --xr` has no marker and keeps the dock.

- **The contexts.** With the marker, bevy\_egui's primary context is not created, since it would latch onto the first eye camera. `follow_surfaces` spawns one image-target camera for `UiSurface::Panel`'s quad and one for the first `WristMenu` quad, each rendering to its quad's `WorldPanel.image` with its own egui context and schedule (`PanelPass`, `WristPass`), at order −1 so the panels drawn this frame are seen this frame, on no render layer so they draw no scene (PRD #452's spike check 3, Q-294). A camera whose quad, image or surface is gone is despawned, so a resized panel's new image gets a new camera.
- **Size.** The panel contexts' zoom is Q-267's factor times `[general] ui_scale`, which `persist` applies beside the screen's; every text style is raised to §1.8's smallest text and every interact height to its smallest target at the default size, both scaling with `ui_scale`, larger egui sizes kept (Q-267, Q-293).
- **The main panel's layout** (Q-294). A tab row with the desktop's tabs and Comfort (`Tab::PANEL`), the tab's content in a scroll area, and the toast line at the bottom. Comfort is the panel's only: `persist`'s section editing the `[locomotion]` options, the UI scale and high contrast with sliders and buttons, which a ray can drag and press (Q-278). The Playback tab starts with the bar's play, step and readout row. The Environment tab has a Recenter button, panel only, writing `Intent::Recenter`: the desktop has no recenter binding, so it is the one place the action is reachable (§1.8 User interface, D-17, Q-T452.2). The training cameras and the request replay are sub-pages (`Page`), opened by buttons in the Scene and Library tabs, and an open question (unload, load scene, replace) is a sub-page with its Yes and No; every sub-page replaces the tab row with one Back button, which answers a question No and otherwise returns to the tab. The mouse-only items are left out: the dock's collapse and resize, Help's key line and the screen-only sections. F2's hide and `capture`'s hidden frame apply to the screen only. Nothing draws a hover tooltip; a newly hovered widget plays the hover cue.
- **The wrist menu's buttons** (Q-291). Five square buttons in §1.8's order (play or pause, labelled by the clock's state; passthrough; main panel; reset pose; fit), sized from Q-265's 3 cm on the quad and spaced evenly. Reset pose and fit give one `Intent::Instance` per selected instance and none with nothing selected; play or pause is `PlaybackCommand::Toggle`, the panel button `Toggle(Feature::Panel)`, passthrough `Toggle(Feature::Passthrough)`; each press plays the click cue. Until M-6 builds passthrough, its button's first press in a run raises E-XR-UNSUPPORTED's warning toast and every later press logs the warning (Q-292, Q-161).

**The panel pointer** (§1.8, I-11, Q-263, Q-279, Q-290). Each `PanelPointer` of the last frame becomes, before egui takes its input, the pointer events of the context rendering to its panel's image, in order, whatever `UiSurface` holds (so the wrist menu's quad is reached too): the move to the hit, the select presses and releases there, then the scroll as one wheel event in points, egui's sign kept. The pixel and the scroll are divided by the context's pixels per point, its zoom included, as bevy\_egui sizes an image target's screen in points; a pixels per point that is not positive and finite counts as 1 (Q-290). A context that had the pointer and gets no message in a frame receives `PointerGone`. The grab presses are `ftgsxr-xr`'s panel's, for the title bar (`ftgsxr-xr/panel.md`).

## Screenshots (`capture`)

F12's `Intent::Screenshot` becomes a `ScreenshotRequest` for the desktop camera, else the lowest-order active camera that renders to no image (Q-T452.1: never a panel's camera), captured from that camera's own render target (Q-212, spike check 4's fallback). The UI is hidden for the captured frame (`UiState::hide_for_one_frame`). One screenshot is in flight at a time, and one Bevy never answers is given up with a warning toast (Q-213). The PNG is encoded with `image` as 8-bit RGB at the target's full size (Q-214), an iTXt chunk with the version, the models' identities and poses, the clock and the camera is inserted after IHDR (Q-150), and the file is written atomically under the screenshots directory, named by the UTC date and time (Q-215, §1.11, Q-14).
