# openftgs-xr — Specification & Architecture

## 0. Purpose, provenance, notation and document map

This document specifies an Apache-2.0 Rust workspace named `openftgs-xr` that implements a player for openftgs models generated by `openftgs`, built twice from one codebase on Bevy and OpenXR: a Linux desktop player with keyboard and mouse, and a Meta Quest 3 OpenXR app with controllers, hand tracking and passthrough. Application code is Rust and shaders are WGSL; a minimal Kotlin or Java shim covers the Android APIs with no native path; Python appears only in dev tooling (owner rule, 2026-10-29).

The player loads the files openftgs writes (openftgs §2.2): the exchange model `ftgs-if`, the full checkpoint `ftgs-checkpoint`, and, for its headless conformance command, `ftgs-render-request`; it writes `ftgs-renders`. It renders the FreeTimeGS primitives (Wang et al., CVPR 2025) at any time, with the mathematics of openftgs E1–E6 restated here in raw time units, places several models in a room, plays them back, and lets the user grab, move and resize them. Together with the sources the rules below allow, this document is all an implementer needs; `docs/spec/openftgs-spec.md` is the reference for the files it reads and is never edited here.

**Source rules.** Owner rules of 2026-10-11, 2026-10-15 and 2026-10-29, recorded in `CLAUDE.md` and restated here so the spec carries them. Implementers may consult the FreeTimeGS paper, the papers it cites and the general Gaussian-splatting literature; the openftgs repository (documentation and source code, Apache-2.0, in the local clone `$OPENFTGS_REPO`, its license file read first); the openftgs-synth dataset (CC0-1.0: data files, `DATASET_CARD.md`, `ASSETS.md`, `SHA256SUMS`; never its GPL generator's code); and third-party software by its license class:

## 1. Specification

### 1.1 Scope and platforms

openftgs-xr is one workspace with two builds \[R: two apps, one codebase\]:

| Build | Target | Entry | Display and input | OpenXR |
| --- | --- | --- | --- | --- |
| Desktop player | Linux x86\_64, Vulkan through wgpu, X11 or Wayland through winit | the `ftgsxr` binary | one window, keyboard and mouse (§1.7) | optional: the same binary runs the XR features against the system's OpenXR runtime (Monado for development and tests, §1.1 below) |
| Quest app | Meta Quest 3 and Quest 3S, Android arm64-v8a on Horizon OS, Vulkan, the Khronos OpenXR loader | the Android app packaging the `ftgsxr_quest` shared library | the headset's two eyes; Touch Plus controllers and hand tracking (§1.8); passthrough (§1.9) | required |

Both builds share every feature that does not need a headset or a window: loading and validating models (§1.2), rendering (§1.3, §1.4), the library and its sources (§1.5), playback (§1.6), settings and files (§1.11), diagnostics (§1.13). The desktop build adds its camera, keyboard and mouse (§1.7) and the headless commands (§1.7); the Quest build adds XR interaction (§1.8), passthrough and the environment features (§1.9), and the Android platform layer (§2.5). A feature that one build cannot offer (passthrough on the desktop, a mouse on the headset) is absent from that build's UI rather than disabled.

**XR on the desktop.** The desktop binary started with `--xr` runs the XR build's session, rendering and interaction against whatever OpenXR runtime the loader finds (§2.5). With Monado's simulated or qwerty driver it serves the integration tests I-n and development without a headset. Passthrough, environment depth, hand tracking and anchors need the headset's runtime and are reported as unavailable on the desktop (§1.9).

**Non-goals.** Training or editing primitives (openftgs trains); other headsets as tested targets (any OpenXR runtime may work through the same code, but only the Quest 3 is tested, see the reference hardware below); Windows and macOS (not forbidden, not tested); WebXR; multi-user sessions; video recording (screenshots only, §1.7).

**Reference hardware** (owner, 2026-10-29). The desktop budgets of §1.12 are measured on a Linux PC with an NVIDIA RTX 4090, the headset budgets on a Meta Quest 3 through adb. Monado on the desktop runs the `xr` test lane (§3.3).

### 1.2 Input models

The player reads three kinds of model files, in this order of preference: the exchange model, which every openftgs run can export; the training checkpoint; and the static PLY snapshot openftgs writes for viewers. Every reader validates before anything is uploaded to the GPU; a file that fails validation is reported with the rule it broke (§1.15) and nothing is loaded.

#### The exchange model `ftgs-if` v1 \[O: openftgs §2.2\]

A safetensors file. The container follows the safetensors format: an 8-byte little-endian unsigned header length, a UTF-8 JSON header that begins with `{` and may be padded with spaces, then the tensor data, little-endian and row-major, each tensor at the `data_offsets` its header entry gives, relative to the start of the data; `__metadata__` is a map of strings to strings; a header above 100 MB is refused; no alignment of the data is guaranteed, so a reader casts in place when the offset is aligned and copies otherwise \[L: safetensors README\].

| Key | Dtype | Shape | Value |
| --- | --- | --- | --- |
| `position` | float32 | \[N, 3\] | μx, world units of the camera poses |
| `time_center` | float64 | \[N\] | τ₀ + μt·T\_τ, raw τ |
| `duration` | float64 | \[N\] | s·T\_τ, units of τ, > 0 |
| `velocity` | float32 | \[N, 3\] | v/T\_τ, world units per unit of τ |
| `scale` | float32 | \[N, 3\] | exp(â), world units, > 0 |
| `rotation` | float32 | \[N, 4\] | unit quaternion (w, x, y, z) with w ≥ 0; where w = 0 the first nonzero component is positive |
| `opacity` | float32 | \[N\] | sigmoid(ô), in (0, 1); openftgs clamps it to \[10⁻⁷, 1 − 10⁻⁷\] |
| `sh` | float32 | \[N, (L+1)², 3\] | SH coefficients in gsplat's basis order (E4); color by E4 |

Metadata, as openftgs writes it (openftgs `io.write_exchange`): `format` = `ftgs-if`; `version` = the decimal major version `1` (the pattern is `major[.minor]`); `sh_degree` = L in decimal; `time_unit` = the unit of τ (openftgs's converters write `s`); `tau0` and `tau1` = τ₀ and τ₁ as shortest round-trip decimal floats; `producer` = the producing software (`openftgs <version>`); `render_conventions` = a compact JSON object with the keys `alpha_max` (0.999), `eps2d` (0.3), `near` (0.01), `far` (1e10), `alpha_skip` (1/255), `transmittance_stop` (1e-4), `pixel_center_offset` (0.5), `background` (three numbers in \[0, 1\], the one the model was trained against, openftgs D-84), `jacobian_clamp_margin` (0.15), `screen_extent_rule` (`opacity_aware`), `screen_extent_max` (3.33) and `rasterize_mode` (`classic`) \[O: openftgs D-73\]. The values in parentheses are openftgs's and the defaults of E6 and E7.

**Reader rules** \[O: openftgs `io.read_exchange`, openftgs `io.validate_exchange`\]. The reader rejects the file unless: `format` is `ftgs-if` and `version` has major 1 (another major is rejected, a minor part ignored); `sh_degree`, `tau0`, `tau1` and `time_unit` are present and the first three parse as numbers, `sh_degree` ∈ {0, 1, 2, 3}; τ₀ and τ₁ are finite with τ₀ ≤ τ₁; every tensor of the table is present with its dtype and shape, N ≥ 1 and the same N throughout; every value is finite; `duration` > 0 and `scale` > 0 everywhere; every `rotation` has norm > 10⁻⁸ (a reader accepts non-unit quaternions and normalizes them; only writers must emit unit ones); every `opacity` lies in (0, 1); with a single timestamp (τ₀ = τ₁) every `time_center` equals τ₀ and every `velocity` is 0 \[O: openftgs D-71\]. `producer` is optional (empty when absent). `render_conventions` is optional: absent, the background is black; present, it must be a JSON object, and a `background` entry must be three numbers in \[0, 1\] \[O: openftgs D-84\]. Unknown tensors and unknown metadata keys are ignored. The player goes beyond openftgs's readers in one respect: it honors the numeric entries of `render_conventions` (D-39), so a model from another producer renders with that producer's constants (§1.3 E6, E7); openftgs's own files carry the defaults.

**Single-timestamp models.** When τ₀ = τ₁, `duration` and `velocity` use a time unit of 1 instead of T\_τ \[O: openftgs D-70\], the velocities are 0 and the model is static: σt ≡ 1 at every τ (E2, D-9) and the playback clock has no effect on it.

**Model identity.** A model's identity is the SHA-256 of the file's bytes, computed while loading (D-40); it keys the saved pose (§1.5), the thumbnail cache and the library entry. Two files with equal bytes are one model wherever they come from.

#### The checkpoint `ftgs-checkpoint` v1 \[O: openftgs §2.2\] \[+\]

A directory. The player reads `manifest.json` and `params.safetensors`; the other files (optimizer, statistics, generators, sampler) are ignored. `manifest.json` carries `format` = `ftgs-checkpoint`, `version` = 1 (an integer), `iteration`, `config` (openftgs's `TrainConfig`), `tau0`, `tau1`, `spatial_scale` (S, openftgs D-27), `frame_dt` (Δt\_f in normalized time, openftgs E14), `sh_degree`, `seed`, `scene_sha256`, `time_unit` (defaults to `s`), `versions` and `files` (the SHA-256 of every other file) \[O: openftgs `io.save_checkpoint`\]. `params.safetensors` holds the nine stored tensors of openftgs §1.1 in float32 with metadata `format` and `version` like the manifest's: `means` \[N, 3\], `times` \[N\], `log_durations` \[N\], `velocities` \[N, 3\], `log_scales` \[N, 3\], `quats` \[N, 4\] (w, x, y, z, unnormalized), `opacity_logits` \[N\], `sh0` \[N, 1, 3\], `shN` \[N, (L+1)² − 1, 3\].

The player activates them into the exchange form of the table above, with T\_τ = τ₁ − τ₀ and T′ = T\_τ when T\_τ > 0, else 1 \[O: openftgs §1.1 activations, openftgs E14, openftgs D-70\]: `position` = `means`; `time_center` = τ₀ + `times`·T\_τ (so τ₀ for every row when T\_τ = 0); `duration` = exp(`log_durations`)·T′; `velocity` = `velocities`/T′; `scale` = exp(`log_scales`); `rotation` = `quats` normalized, with the canonical sign; `opacity` = sigmoid(`opacity_logits`) computed in float64 and clamped to \[10⁻⁷, 1 − 10⁻⁷\]; `sh` = `sh0` followed by `shN` along the coefficient axis. The exchange validation rules then apply; a checkpoint whose `files` entry for `params.safetensors` disagrees with the file's SHA-256 is refused. The checkpoint's `spatial_scale` and `frame_dt` serve as hints (§1.5 placement, §1.6 frame step); the model identity is the SHA-256 of `params.safetensors`. The checkpoint's `config.background` is the background the colors were trained against, as `ftgs export` would record it \[O: openftgs D-84\].

#### The PLY snapshot \[O: openftgs `io.write_ply`\] \[+\]

openftgs can export a static snapshot of a model at one time as a PLY file for 3DGS viewers: binary little-endian, one `vertex` element with float32 properties `x y z`, `nx ny nz` (zero), `f_dc_0 f_dc_1 f_dc_2`, `f_rest_0 … f_rest_{3(K−1)−1}` (channel-major: the K − 1 higher coefficients of the red channel, then green, then blue), `opacity` (a logit), `scale_0 scale_1 scale_2` (logs) and `rot_0 rot_1 rot_2 rot_3` (w, x, y, z). The player reads such a file as a single-timestamp model: `position` = (x, y, z); `time_center` = 0 and `velocity` = 0 with τ₀ = τ₁ = 0 and `time_unit` = `s`; `duration` = 1; `scale` = exp(scale); `rotation` normalized with the canonical sign; `opacity` = sigmoid(opacity) clamped as above; `sh` reassembled as \[N, K, 3\] with K = 1 + (number of `f_rest` properties)/3, which must be (L+1)² for L ∈ {0, 1, 2, 3}; the normals are ignored; the background is black; the producer is the PLY header's comment line when one names it, else empty. A PLY with other property names, types or an ASCII format is refused (D-41). Other 3DGS viewers' PLY files that follow the same property names load the same way; this is the only non-openftgs input and it is incidental to the openftgs export.

#### Load options

Loading applies, in this order, the options of the active quality tier (§1.12) or of the explicit load request \[D-12, D-13\]:

1. **SH cap.** With a cap L′ < L, the bands above L′ are dropped (coefficients (L′+1)² onward); E4 then evaluates degree L′. A tier's cap above L is the identity. The headless `render` command renders at the request's `sh_degree` (null = the model's L); a request degree above L is the error E-REQ-DEGREE, exit 2, as openftgs's `render` behaves \[O: openftgs §2.2; Appendix A row 5\].
2. **Storage precision.** The fields the tier marks half-precision (`velocity`, `scale`, `rotation`, `opacity`, `sh`; never `position`, the rebased time center nor `duration`, whose raw-unit values could overflow half precision) are stored on the GPU as IEEE half floats, rounded to nearest even; §1.12 bounds the error. The CPU copy keeps the file's precision.
3. **Time rebasing.** Time centers are stored on the GPU as float32 τ − τ₀ and durations as float32, so a long raw timestamp (seconds since an epoch, say) keeps its precision: the absolute error of τ − time\_center stays below 10⁻⁶ T\_τ, so E2's argument errs by less than 10⁻⁶ T\_τ/duration (U-7).
4. **Memory check.** The static GPU bytes the model needs under the options (§1.12's table) are compared with the tier's memory budget; a model that does not fit is refused with a message giving N and the bytes (D-13). With the explicit "reduce to budget" option the player keeps the N\_budget primitives of highest importance score opacity·scale\_x·scale\_y·scale\_z and labels the instance as reduced in the UI; nothing is reduced silently.
5. **Temporal ordering.** Rows are permuted into persistent-first-then-by-time-center order for the temporal index (E3, D-10); the permutation is kept so that diagnostics can name file rows.

### 1.3 Equations

The player's behaviour is fixed by equations E1–E16. E1–E7 restate openftgs E1–E6 in raw time units, with the pose and the view added; E8–E16 are the player's own and carry their tags. Every constant E6 and E7 name comes from the model's `render_conventions` block (§1.2, D-39), with openftgs's values as the defaults written in parentheses.

**E1 · Motion** \[O: openftgs E1, openftgs E14\]

```latex
\mu_x(\tau) = \mathrm{position} + \mathrm{velocity}\,(\tau - \mathrm{time\_center})
```

Linear for every τ, including outside \[τ₀, τ₁\]; no clamping. A model instance evaluated outside its span is flagged as extrapolating (§1.6). With a single timestamp the velocities are 0 and the position never moves. The world position of a primitive is E5's μ^S.

**E2 · Temporal and effective opacity** \[O: openftgs E3, openftgs E4; D-9\]

```latex
\sigma_t(\tau) = \exp\!\Big(-\tfrac12\Big(\frac{\tau - \mathrm{time\_center}}{\mathrm{duration}}\Big)^2\Big),\qquad \sigma_{eff}(\tau) = \sigma_t(\tau)\;\mathrm{opacity}
```

Unnormalized: the peak is 1 at τ = time\_center. With a single timestamp (τ₀ = τ₁) σt ≡ 1 at every τ, since openftgs evaluates such a model at t ≡ 0 \[O: openftgs §1.4 Time\]; the raw formula is not applied (D-9). On the GPU the argument is computed from the rebased float32 values, ((τ − τ₀) − (time\_center − τ₀))/duration; the CPU reference computes in float64 (U-6).

**E3 · Temporal active set** \[O: openftgs D-55, openftgs E6; D-10\]

```latex
\mathrm{active}_i(\tau) \iff |\tau - \mathrm{time\_center}_i| \le \mathrm{duration}_i\,\sqrt{2\ln(\mathrm{opacity}_i/\alpha_{skip})}\qquad (\mathrm{opacity}_i > \alpha_{skip})
```

α\_skip is the model's `alpha_skip` (1/255 in openftgs's files; D-39). A primitive with opacity ≤ α\_skip is never active: its effective opacity cannot reach α\_skip, and E6 culls it the way openftgs's render backends do. The cull pass decides activity exactly, by the test σ\_eff(τ) < α\_skip on every row it visits, so images never depend on the index below (D-10). The temporal index restricts the rows visited: rows are ordered persistent-first, then by time center; a row is persistent when its window \[time\_center − w, time\_center + w\], with w the right-hand side above, covers \[τ₀, τ₁\]. A query at τ visits every persistent row and the contiguous run of transient rows whose time centers lie in \[τ − w\_max, τ + w\_max\], where w\_max is the widest transient window. Windows are widened as openftgs widens its buckets: opacity multiplied by (1 + 10⁻⁴) inside the logarithm and 10⁻⁶·T′ added to w, with T′ = T\_τ (1 for a single timestamp) \[O: openftgs render.py, openftgs D-55\]. The visited set is a superset of the active set at every τ (U-8).

**E4 · Color** \[O: openftgs E2, openftgs D-4; constants and signs: openftgs `sh.py`, gsplat 1.5.3\]

```latex
c_i(v) = \max\Big(0,\ \sum_{l=0}^{L'}\sum_{m=-l}^{l} c_{i,lm}\,Y_{lm}(d_i) + 0.5\Big),\qquad d_i = \frac{\mu_{x,i}(\tau) - o_{v,m}}{\lVert \mu_{x,i}(\tau) - o_{v,m}\rVert}
```

The maximum is per channel; there is no clamp above 1. L′ is the loaded degree (§1.2 load options). o\_{v,m} = P\_m⁻¹(o\_v) is the eye of view v expressed in model m's space, so that rotating a model rotates its view-dependent appearance with it; in shared-center mode (D-4) o\_v is the midpoint of the two eyes; in a headless render it is the request camera's center −R\_wᵀ t\_w \[O: openftgs §1.4\]. The real SH basis Y\_lm, in gsplat's band order with its signs (the Condon–Shortley phase kept), for a unit direction d = (x, y, z):

| l | Coefficient order m = −l … l | Values |
| --- | --- | --- |
| 0 | Y₀₀ | C₀ |
| 1 | Y₁,₋₁, Y₁,₀, Y₁,₁ | −C₁ y, C₁ z, −C₁ x |
| 2 | Y₂,₋₂ … Y₂,₂ | C₂,₁ xy, −C₂,₁ yz, C₂,₀ (3z² − 1), −C₂,₁ xz, C₂,₂ (x² − y²) |
| 3 | Y₃,₋₃ … Y₃,₃ | −C₃,₃ y(3x² − y²), 2C₃,₂ xyz, −C₃,₁ y(5z² − 1), C₃,₀ z(5z² − 3), −C₃,₁ x(5z² − 1), C₃,₂ z(x² − y²), −C₃,₃ x(x² − 3y²) |

with C₀ = 0.28209479177387814 (1/(2√π)), C₁ = 0.4886025119029199 (√(3/(4π))), C₂,₀ = 0.31539156525252005 (¼√(5/π)), C₂,₁ = 1.0925484305920792 (½√(15/π)), C₂,₂ = 0.5462742152960396 (¼√(15/π)), C₃,₀ = 0.3731763325901154 (¼√(7/π)), C₃,₁ = 0.4570457994644658 (¼√(21/(2π))), C₃,₂ = 1.445305721320277 (¼√(105/π)), C₃,₃ = 0.5900435899266435 (¼√(35/(2π))). The `sh` tensor's coefficient axis follows this order, the DC term first; a degree-0 color is C₀·c₀₀ + 0.5.

**E5 · Covariance and pose** \[O: openftgs E5; D-11, D-43\]

```latex
\Sigma_i = R(q_i)\,\mathrm{diag}(\mathrm{scale}_i)^2\,R(q_i)^\top,\qquad \mu^S_i = s_m\,R(q_m)\,\mu_{x,i}(\tau) + t_m,\qquad \Sigma^S_i = s_m^2\,R(q_m)\,\Sigma_i\,R(q_m)^\top
```

q\_i is the file's (w, x, y, z) normalized; R is openftgs E5's matrix. P\_m = (t\_m, q\_m, s\_m) is the instance's pose, a similarity transform with a uniform scale, so that E4's directions and E6's projection stay exact under it; a non-uniform scale is never applied. Velocities for the debug view transform as s\_m R(q\_m) velocity. In stage space the ground is y = 0 and y points up (§1.14).

**E6 · Projection** \[O: openftgs E6, openftgs §1.4; X: XrFovf, XrPosef; D-39\]

A view v has a camera in openftgs's conventions: a world-to-camera rotation R\_w and translation t\_w with OpenCV axes (x right, y down, z forward), a pinhole with f\_x, f\_y, c\_x, c\_y in pixels under the continuous pixel convention (the image spans \[0, W\] × \[0, H\], pixel (u, v) is sampled at (u + 0.5, v + 0.5)), and the image size W × H. It is built per source:

- headless: K and `world_to_camera` of the request item \[O: openftgs §2.2\];
- desktop: the fly or orbit camera's pose (position p, orientation q in stage space, looking along −z with y up) and vertical field of view φ: R\_w = diag(1, −1, −1) R(q)ᵀ, t\_w = −R\_w p, f\_y = (H/2)/tan(φ/2), f\_x = f\_y, c\_x = W/2, c\_y = H/2;
- XR: the OpenXR view's pose (p, q) in stage space and its XrFovf angles (a\_L, a\_R, a\_U, a\_D), with a\_L and a\_D negative, and the swapchain image size W × H: R\_w = diag(1, −1, −1) R(q)ᵀ, t\_w = −R\_w p, f\_x = W/(tan a\_R − tan a\_L), c\_x = −f\_x tan a\_L, f\_y = H/(tan a\_U − tan a\_D), c\_y = f\_y tan a\_U.

```latex
x_c = R_w\,\mu^S + t_w,\qquad \mu' = \Big(f_x\,\tfrac{x_c}{z_c} + c_x,\ f_y\,\tfrac{y_c}{z_c} + c_y\Big),\qquad \Sigma' = J\,R_w\,\Sigma^S\,R_w^\top J^\top + \epsilon\,I_2
```

- J is the EWA Jacobian of the perspective projection at x\_c, with x\_c/z\_c clamped to \[−(c\_x/f\_x + m\,W/f\_x), (W − c\_x)/f\_x + m\,W/f\_x\] and y\_c/z\_c likewise with H, f\_y, c\_y, where m is `jacobian_clamp_margin` (0.15); the clamp applies to J only, not to μ′.
- ε is `eps2d` (0.3). A primitive is culled when z\_c < `near` (0.01) or z\_c > `far` (10¹⁰), z\_c in stage metres, when det Σ′ ≤ 0, or when its box lies wholly outside the image. A non-finite value anywhere in its projection culls it too, and the HUD counts such primitives; the headless render checks its output and exits 3 when any value is not finite, as openftgs's does.
- The screen extent is e = min(`screen_extent_max` (3.33), √(2 ln(σ\_eff/α\_skip))) standard deviations, α\_skip the model's `alpha_skip` (1/255), (`screen_extent_rule` = `opacity_aware`); the radii are r\_x = ⌈e √Σ′₀₀⌉ and r\_y = ⌈e √Σ′₁₁⌉ in whole pixels; the box is μ′ ± r. A primitive is visible when both radii are positive. The conic is Σ′⁻¹.
- A `screen_extent_rule` or `rasterize_mode` other than openftgs's is reported as a warning and rendered as `opacity_aware` and `classic` (D-39).

**E7 · Compositing** \[O: openftgs E6, openftgs D-76 (its background clause); D-6, D-7, D-14, D-48\]

```latex
\alpha_i(p) = \min\!\Big(\alpha_{max},\ \sigma_{eff,i}(\tau)\,\exp\!\big(-\tfrac12\,(p-\mu'_i)^\top \Sigma'^{-1}_i\,(p-\mu'_i)\big)\Big)\,w_{occ,i}(p)
```

```latex
(C, A) \leftarrow \big(c_i\,\alpha_i + C\,(1-\alpha_i),\ \alpha_i + A\,(1-\alpha_i)\big)\ \text{for the primitives in far-to-near order (E8)},\qquad C_{final} = C + (1-A)\,c_{bg}
```

α\_max is `alpha_max` (0.999); a term is skipped when its quadratic form is negative or α < `alpha_skip` (1/255), the skip tested before the occlusion weight w\_occ (E13; 1 when occlusion is off). The layer is cleared to (0, 0, 0, 0) and blended with the premultiplied over operator, so the far-to-near accumulation equals openftgs E6's front-to-back sum. c\_bg is the background: the request's in a headless render, the environment's in VR mode (§1.9), and absent in passthrough mode, where the layer's (C, A) reach the compositor premultiplied (D-14). Colors are file-encoded values, blended as such (D-6); §1.4 says how the layer is shown. The transmittance stop at 10⁻⁴ is not applied (D-7): openftgs excludes the primitive that would bring the transmittance T to 10⁻⁴ or below, and everything behind it, which hardware blending cannot. At a pixel whose transmittance T lies in (10⁻⁴, 10⁻⁴/(1 − α\_max)\] = (10⁻⁴, 0.1\] when a primitive of α ≥ 1 − 10⁻⁴/T arrives, the player adds up to T·c per channel and T in alpha that openftgs leaves out; everywhere else the difference is below 10⁻⁴. Accumulation is in 16-bit floats (D-35). §3.2 measures both against openftgs's reference.

**E8 · Sort key** \[D-48, D-33, D-4\]

```latex
k_i = \mathrm{bits}_{u32}(z_{c,i}),\qquad \bar k_i = 2^{32} - 1 - k_i,\qquad \text{draw order: ascending } \bar k
```

z\_c > 0 after E6's near cull, and the IEEE bit pattern of a positive float orders as an unsigned integer, so ascending k̄ is far-to-near. The `Depth16` tier keeps the top 16 bits of k̄. The depth is the view's camera-space z of μ^S, per view; in shared-center mode (D-4) it is the z along the forward axis of the midpoint pose, used by both eyes. Ties keep the record order (the sort is stable).

**E9 · Playback clock** \[R: playback; D-32\]

```latex
\tau_m(T) = \tau_{0,m} + r_m\,(T - o_m),\qquad T \in [0, T_{len}],\qquad T_{len} = \max_m\Big(o_m + \frac{T_{\tau,m}}{r_m}\Big)
```

T is the clock in seconds; r\_m converts seconds to the model's `time_unit` (1 for `s`, 1000 for `ms`; any other unit is 1 with a warning, D-32); o\_m is the instance's offset (seconds, default 0). The instance's end rule then applies: hold (default) clamps τ\_m to \[τ₀,m, τ₁,m\]; extrapolate leaves it and flags the instance. The clock advances by speed·Δt while playing, speed ∈ \[−4, 4\] \ {0}; its loop mode wraps (loop), reflects (ping-pong) or pauses at the end (once); a scrub sets T. A single-timestamp model ignores τ (D-9) and does not count toward T\_len, whatever its offset (`ModelTime::length_s`, which gives o\_m + T\_τ/r\_m, is not consulted for it); when every instance is single-timestamp, T\_len = 0 and the clock is idle.

**E10 · Ray selection** \[R: grab; D-42\]

B\_m is the model's axis-aligned box in model space: the box over μx(τ) at τ = τ₀ + k T\_τ/8, k = 0 … 8 (one sample for a single timestamp), of every primitive with opacity > α\_skip, expanded by 3·max\_i max(scale\_i). A ray with origin o and unit direction d in stage space is taken into model space (o\_m = P\_m⁻¹ o, d\_m = R(q\_m)ᵀ d / s\_m) and tested against B\_m:

```latex
t_{in} = \max_{a\in\{x,y,z\}} \min\!\Big(\frac{B^{min}_a - o_{m,a}}{d_{m,a}},\ \frac{B^{max}_a - o_{m,a}}{d_{m,a}}\Big),\quad t_{out} = \min_{a} \max(\cdot,\cdot),\quad \text{hit} \iff t_{in} \le t_{out},\ t_{out} \ge 0,\ \max(t_{in}, 0) \le t_{max}
```

t\_max = 10 m. The selected instance is the hit one with the smallest max(t\_in, 0); the hit point o + max(t\_in, 0)·d is where a grab takes hold. A zero component of d\_m uses the limit (±∞) in the usual slab way.

**E11 · Grab transforms** \[R: grab, resize; D-43\]

One hand: at the grab's start M = H₀⁻¹ P₀, with H the hand's pose (a rigid transform) and P the instance's pose; every frame P = H M, so the instance keeps its place in the hand. Two hands, with positions a, b (a₀, b₀ at the start), midpoint m = (a + b)/2 and d = b − a:

```latex
s' = \mathrm{clamp}\Big(s_0\,\frac{\lVert b - a\rVert}{\lVert b_0 - a_0\rVert},\ s_{min},\ s_{max}\Big),\qquad \theta = \operatorname{atan2}\big((\bar d_0 \times \bar d)\cdot\hat y,\ \bar d_0\cdot\bar d\big),\qquad P' = T(m)\,R_{\hat y}(\theta)\,\mathrm{Scale}\big(\tfrac{s'}{s_0}\big)\,T(-m_0)\,P_0
```

where d̄ is d projected on the horizontal plane (ŷ the stage up axis) and normalized; s\_min = 0.01, s\_max = 100. The instance scales about and follows the hands' midpoint and turns with the hands' yaw; the "free rotation" option replaces R\_ŷ(θ) by the shortest rotation taking d₀ to d.

**E12 · Locomotion** \[R: locomotion; D-17, D-44\]

```latex
\mathbf v = v_{max}\,R_{yaw}(\psi_{head})\,(x_s,\ 0,\ -y_s),\qquad \Delta \mathbf p = \mathbf v\,\Delta t,\qquad \Delta\psi = \begin{cases} \pm\theta_{snap} & \text{snap turn, on a flick of } x_t \\ \omega\,x_t\,\Delta t & \text{smooth turn}\end{cases}
```

(x\_s, y\_s) is the move stick and x\_t the turn stick after the response r(x) = sign(x)·((|x| − d)/(1 − d))² for |x| > d and 0 otherwise, with the dead zone d = 0.15, applied per axis; ψ\_head is the head's yaw; v\_max = 2 m/s (1–4 m/s), θ\_snap = 45° (30°, 45° or 90°), ω = 60°/s. In VR mode the rig moves by Δp and turns by Δψ about the head's position, so a turn does not translate the user. In passthrough mode the sticks move nothing: the real room cannot move, and moving the content instead was rejected (owner decision, 2026-10-29, D-17); the user walks. Walking needs no equation: the tracked head moves in stage space.

**E13 · Occlusion** \[R: occlusion; X: XR\_META\_environment\_depth; D-16, D-45\]

For a fragment of primitive i in view v, p\_f is the point on the view ray through the fragment at the primitive's depth z\_c,i. The environment depth image of the view, with the pose and field of view the runtime gives for it (a camera built as in E6), yields at p\_f's projection a stored depth, converted to metres z\_e by the inverse of the depth image's projection (its nearZ and farZ; an infinite far plane when farZ < nearZ) \[X\]. Then

```latex
w_{occ} = \begin{cases} \mathbb 1\,[\,z_f \le z_e + \delta\,] & \text{hard} \\ 1 - \mathrm{smoothstep}(z_e - \delta,\ z_e + \delta,\ z_f) & \text{soft}\end{cases},\qquad \delta = 0.05\ \mathrm{m}
```

with z\_f the depth of p\_f in the depth camera. A fragment outside the depth image, or one whose sample is invalid, gets w\_occ = 1. Hand removal is the provider's option (§1.9).

**E14 · Light estimate and color transform** \[R: color matching; A: Passthrough Camera API; D-15, D-38\]

Over a region Ω of a camera frame (global: the frame; local: the pixels whose environment depth lies within d\_m ± Δ of the instance's distance d\_m from the eye, Δ = 0.5 m, falling back to the frame when fewer than 1 % of its pixels qualify), the estimate is the mean luma Ȳ and the mean RGB (r̄, ḡ, b̄) after the BT.709 conversion of the frame's YUV, smoothed by an exponential moving average with a 0.5 s time constant. A reference E\_ref is captured when matching is enabled and whenever the user re-captures it. The gains and the transform are

```latex
g = \Big(\frac{\bar Y}{\bar Y_{ref}}\Big)^{\gamma},\qquad w_c = \frac{\bar c/\bar Y}{\bar c_{ref}/\bar Y_{ref}}\ \text{scaled to mean 1},\qquad c'_{lin} = \mathrm{clamp}\big(g\,w \odot c_{lin},\ 0,\ 1\big)
```

with γ = 0.5 and g, w clamped to \[0.25, 4\]. The transform applies to each primitive's E4 color in linear light (decode the file's sRGB encoding, multiply, re-encode) before E7, so blending stays in the file's space (D-6). Manual mode sets g = 2^EV from an exposure slider (EV ∈ \[−4, 4\]) and w from temperature t and tint u sliders in \[−1, 1\]: w = (1 + 0.4 t, 1 − 0.4 u, 1 − 0.4 t) scaled to mean 1 (warmer for positive t, greener for negative u); grey-world mode needs no reference: w\_c = Ȳ/c̄ scaled to mean 1 and g = 1. Without camera access (permission denied, unsupported OS version, desktop) only manual mode is offered (D-15).

**E15 · Conformance metrics** \[O: openftgs §3.3 L1; D-46\]

For a request item rendered by openftgs's reference backend (A) and by the player (B), both clamped to \[0, 1\] per channel (D-46):

```latex
\mathrm{PSNR} = 10\log_{10}\frac{1}{\mathrm{MSE}(A, B)},\qquad s = \frac{|\{p : \max_c |A_c(p) - B_c(p)| > 1/255\}|}{W H},\qquad s_\alpha = \frac{|\{p : |\alpha_A(p) - \alpha_B(p)| > 1/255\}|}{W H}
```

MSE is over H·W·3 values; PSNR is ∞ when MSE = 0; a pixel counts in s when any channel differs by more than 1/255 (openftgs leaves the channel rule unstated, D-46). The pass criterion is openftgs's different-rasterizers tier, PSNR ≥ 45 dB and s ≤ 0.5 %, plus the same share for alpha, s\_α ≤ 0.5 % (D-46): a maximum would fail on D-7's isolated pixels.

**E16 · Quality governor** \[+; D-47\]

```latex
e = \frac{f_{gpu}}{f_{budget}},\qquad f_{budget} = \frac{1}{\text{refresh rate}} - 1.5\ \mathrm{ms}
```

f\_gpu is the frame's GPU time (§1.13). After 10 consecutive frames with e > 1.05 the governor steps one knob down; after 120 consecutive frames with e < 0.8 it steps one knob up, in the reverse order. The knobs, each exhausted before the next in step-down order and released in the reverse order: render scale (steps of 0.1 from 1.0 to 0.6), fixed foveation level (+1 up to high, headset only), SH degree cap (−1, down to 1), sort mode (per view → shared center). A tier chosen by hand turns the governor off (§1.12).

### 1.4 Rendering

**Method** \[R: splats rendering; D-3\]. Primitives are drawn as sorted screen-aligned quads with hardware premultiplied-alpha blending, the method of the permissive splat renderers the research surveyed (Appendix A), not as a tile-based compute rasterizer: hardware blending needs no per-pixel sort, no 64-bit atomics and no CPU readback, and it runs on the Quest's Vulkan driver as on the desktop. Its deviations from openftgs's render backends are E7's, bounded by §3.2.

**Per-frame pipeline.** One frame of one view runs these stages; a headset frame runs them for both views, sharing stages 1–4 in shared-center mode (D-4):

1. **Prepare (CPU, per instance).** τ\_m from E9; the temporal index's dispatch ranges for τ\_m (E3); one uniform block per instance: the pose as a matrix with its rotation and scale (E5), τ\_m − τ₀ as float32, the loaded SH degree, the color transform (E14), the render mode and flags. Nothing is read back from the GPU in the frame loop (D-34).
2. **Cull (compute, per instance, per dispatch range).** Per row: σt and σ\_eff (E2; σt ≡ 1 for a single-timestamp model); early exit when σ\_eff < α\_skip (E3); μx(τ) (E1) → μ^S (E5) → camera space; the near and far culls, the frustum cull by the projected box, E6's projection, extent and radii, the determinant guard; the E4 color at the view's eye (or the midpoint, D-4) with the E14 transform applied. A visible row takes a slot in the frame's record buffer by an atomic increment of the visible count in the indirect-draw arguments and writes its record: the per-view record holds μ′, the conic, the half-extents, the premultiplied color and α as four half floats, the depth and flags (48 bytes); the shared-center record holds the stage-space position, Σ^S, the color and the key (64 bytes, 48 with half-precision Σ^S). Centers-mode instances append to a second region with its own count. A slot beyond the capacity C is dropped and raises the overflow flag (D-34).
3. **Size (compute, one workgroup).** Clamps the counts to C and writes the dispatch arguments of the sort passes from the visible count, so the GPU, not the CPU, sizes the frame.
4. **Sort (compute).** A least-significant-digit radix sort of (k̄, slot) pairs (E8): 8-bit digits, four passes (two for `Depth16`), each pass a histogram, a scan and a stable scatter with workgroups of 256 threads, without subgroup operations or decoupled look-back, so it runs the same on Adreno and on desktop GPUs (D-33); every dispatch is indirect from stage 3's arguments.
5. **Draw splats (render pass).** One indirect instanced draw of four-vertex strips in the sorted order into the frame's layer: a 16-bit float RGBA target cleared to (0, 0, 0, 0), blending `One, OneMinusSrcAlpha` on color and alpha, the depth test on against the pass's opaque depth at the record's depth, the depth write off, MSAA off. The vertex stage places the quad at μ′ ± r (per view) or projects the stage-space record for this eye (shared-center mode); the fragment stage evaluates E7's α with the conic, the skip rules and E13's weight, and writes (cα, α).
6. **Draw centers (render pass)** \[R: centers rendering\]. For instances in centers mode, one indirect instanced draw of discs of radius ρ pixels (default 3 at render scale 1, 1–8) at the moved positions, opaque, depth write on, colored by the instance's colormap: the DC color C₀c₀₀ + 0.5 (default), the time center over \[τ₀, τ₁\] (a perceptually ordered colormap), the speed ‖velocity‖ relative to the model's 99th percentile, or the opacity. Centers need no sort.
7. **Resolve (full-screen pass)** \[D-6\]. The layer holds file-encoded premultiplied values. For display, each pixel's color is un-premultiplied, decoded from sRGB to linear light, re-premultiplied and composited over the view target with the over operator, so the engine's linear pipeline shows the file's values unchanged on an sRGB display. In VR mode the background is composited first (E7's c\_bg); in passthrough mode the view target keeps the layer's alpha for the compositor (D-14). A headless render skips the resolve and reads the layer back (§1.7).
8. **Statistics.** A 64-byte block (the two counts, the overflow flag) is copied to a staging buffer and read two frames later for the HUD (§1.13), never in the frame that wrote it.

When no instance's τ\_m, pose, mode or transform changed since the last frame and the view's camera did not move, stages 1–4 are skipped and the previous frame's buffers are drawn again; the output is identical by construction.

**Several models** \[R: load several models; D-5\]. Every instance appends to the same record buffer of a view under one visible count, and one sort orders all of them, so overlapping instances interleave correctly; the draw needs no instance id because each record carries its final color. The capacity C is shared (§1.12): on overflow the HUD shows a warning and the frame drops the rows that did not fit, nondeterministically; the conformance tier sets C to the sum of the loaded models' N.

**Stereo** \[D-4\]. Per-view mode runs stages 1–5 for each eye with that eye's camera: exact, twice the sort. Shared-center mode, the default on the headset, runs stages 1–4 once at the midpoint pose of the two eyes (E4's eye, E8's depth) and only stage 5 per eye, projecting each stage-space record for the eye in the vertex stage: half the sort and record work, with the depth order and the view-dependent color of the midpoint, which §3.2 bounds. The desktop and headless renders have one view.

**Depth and occlusion.** Splats write no depth; they test against the opaque depth of the pass, so the controller models, the hand meshes and the UI panels drawn as opaque geometry occlude them, and the UI panel drawn after them covers them. Centers write depth. The environment's depth occludes through E13 (§1.9). A splat does not occlude engine geometry.

**Backgrounds.** Headless: the request's background (E7). VR mode (§1.9; the desktop is always in VR mode): a solid color, a neutral dark grey (0.1, 0.1, 0.1) by default, with the model's training background offered as a preset, and an optional floor grid at y = 0. Passthrough mode: none; the layer is transparent where no primitive covers it.

**Selection and debug views** \[+\]. The hovered instance shows its box B\_m (E10) as thin lines; the selected instance shows it in the accent color. Optional overlays per instance: velocity vectors for one primitive in k (k = 64 by default), the bounding box at the current time, and a "time slice" tint that colors primitives by how far τ is from their time center.

**Render scale, foveation and refresh rate** are the quality tier's (§1.12). **Pose latency**: the headset's views are predicted by the runtime for the frame's display time; the XR crate's pipelined rendering adds one display period, which applies to the sort pose as to everything else (§2.4).

### 1.5 Scene, library and sources

**Library** \[R: list the models available to load\]. The library is the list of models every configured model source offers. An entry carries its source, name (the file stem), path or URL, size, kind (`ftgs-if`, `ftgs-checkpoint`, `ply`), the header-only information when the source allows it (N, L, τ₀, τ₁, `time_unit`, producer: read from the file's header alone, on HTTP through a range request of the first 8 + header-length bytes, never the whole file), a thumbnail once the model has been loaded (a 256×256 render at τ₀ from a view fitting B\_m, cached by identity), and a state: listed, fetching (with progress), loading, loaded (which instance), failed (with the message). Refreshing a source relists it; entries whose file changed (size, ETag or SHA-256) lose their cached information.

**Sources** \[R: load from a file on the PC, from an HTTP server, from the Quest's storage; D-31, D-49\]:

- *Local directory* (both builds): a directory scanned one level deep for `*.safetensors` files whose header says `ftgs-if`, checkpoint directories holding `manifest.json` with `format` `ftgs-checkpoint`, and `*.ply` files; several directories may be configured. The desktop's default is `<data dir>/models` (§1.11); the Quest's default is the app-external directory `Android/data/<application id>/files/models`, which `adb push` and the MTP connection reach without a picker (D-49).
- *HTTP index* (both builds): a base URL listed through, in order of preference, the player's own manifest `index.json` (§1.11: `format` `ftgsxr-index`, `version` 1, `entries` with `name`, `path`, `kind`, `size`, optional `sha256`, `thumbnail`, `audio`), nginx's `autoindex_format json` listing (an array of `{name, type, mtime, size}`), or an HTML directory listing (Apache's `mod_autoindex`, nginx's HTML autoindex) parsed for its anchors' `href` values, taking names that end with `.safetensors`, `.ply` or `/` and ignoring the parent link; subdirectories list on demand (D-31). Direct URLs of a model file are accepted too. Requests send `If-None-Match` and `If-Modified-Since` from the cache and resume partial downloads with `Range`; a file whose server supports neither is downloaded whole each time its validators change.
- *Picked files* (desktop: the system file dialog; Quest: the Android document picker through the shim, §2.5): one or several files, or a folder tree, added as a source for the session and remembered across sessions when the platform grants persistent access (D-49).
- *Scene files* (§1.11) name their models by source and identity; a model whose source is gone is listed as missing with a "locate" action.

**Download cache.** Each URL maps to `<cache dir>/http/<sha256 of the URL>/` holding the file and a `meta.json` (URL, ETag, Last-Modified, size, the file's SHA-256 once complete, the fetch time). A partial download is resumed with a `Range` request when the validators still match, else restarted. When the index entry or a `SHA256SUMS` or `<name>.sha256` file beside the model gives a digest, the downloaded file must match it or it is discarded with an error. Downloads run one at a time, in the background, with progress and a cancel action; header reads run in parallel. The cache has a size limit (§1.11; least recently used eviction, never of a loaded model's file).

**Loading and unloading** \[R: load, unload, several at once\]. A load reads and validates the file off the main thread (§1.2), packs it for the GPU (§1.2 load options), then uploads it in chunks of at most 64 MB per frame so the frame rate holds; the instance appears when the upload completes. The same model may be loaded twice as two instances. Unloading frees the GPU buffers and the CPU copy at once and keeps the library entry; reloading re-reads the file. Errors (validation, memory budget, I/O) reach the UI with §1.15's texts and leave no partial instance. A checkpoint loads by path: a local one from its directory, an HTTP one once its `manifest.json` and `params.safetensors` are downloaded into one cache entry, which the load then reads as a directory (D-51). Model files are read into memory, never memory-mapped (D-50).

**Instances** \[R: several models\]. An instance has: the model's identity and source, a name (the file stem, editable), visibility, render mode (splats, centers, both, hidden), its pose P\_m, a time offset and end rule (E9), a color transform (E14, identity by default), an optional audio sidecar (§1.10), the overlays of §1.4, and the "reduced" flag of §1.2. The scene panel lists instances; selecting one makes it the target of the pose, time and display controls.

**Poses** \[R: save pose, reset pose; D-11\]. A model loads at the identity pose: the dataset's units are taken as metres and its frame as stage space, which keeps the conformance renders exact. The "fit" action places the instance in front of the user: the longest side of B\_m scaled to L\_fit (1 m by default, 0.25–4 m), the box's center 1.5 m ahead of the head along its yaw and its bottom on the floor y = 0 (desktop: ahead of the camera on the ground plane), after the orientation preset. On the headset the fit is applied automatically on the first load of a model without a saved pose when B\_m's longest side lies outside \[0.1 m, 5 m\]. Orientation presets rotate the model's frame into stage space: Y-up (identity, the default), Z-up (−90° about x, so the model's z becomes up: openftgs-synth's scenes are z-up, metres), −Y-up (180° about x), and a custom rotation; a `ftgs-scene` manifest or a checkpoint beside the model suggests a preset from the mean camera up vector (−R\_wᵀ (0, 1, 0) averaged over its cameras) and the checkpoint's spatial scale S suggests L\_fit = 2S. "Save pose" writes the instance's pose, preset and the fit size into the pose store under the model's identity; a saved pose wins over the identity and the auto-fit on every later load. "Reset pose" returns to the saved pose if one exists, else the identity; a long press (or the panel's second button) forgets the saved pose. "Snap to floor" moves the instance down (or up) until B\_m's bottom touches the floor; "keep upright" (on by default in XR) restricts grabs to yaw rotation (E11).

**Scene files** \[+; D-23\]. A scene file (§1.11, `ftgsxr-scene` v1) records every instance (source, identity, name, pose, visibility, mode, time offset and end rule, color transform, audio), the clock (T, speed, loop mode, range), the environment settings of §1.9 (mode, background, occlusion, lighting mode and reference), the spatial anchor id when one was created (§1.9) and the rig or camera pose. Saving writes the file to the config directory's `scenes/<name>.ftgsxr-scene.json`; loading replaces the current scene after confirmation, fetching missing models from their sources; the most recent eight scenes are listed for one-tap loading.

### 1.6 Playback

**Clock** \[R: playback; E9; D-32\]. One clock T drives every instance. Controls: play and pause (toggle), a scrub bar over \[0, T\_len\] with the time of the selected instance shown in its `time_unit` to three decimals and as a frame number (T/Δ\_frame), speed presets 0.1, 0.25, 0.5, 1, 2 and 4 in both directions, loop modes loop (default), ping-pong and once, a playback range \[T\_a, T\_b\] set from the scrub bar (loop and ping-pong act within it), and a frame step ±Δ\_frame while paused. Δ\_frame is the selected instance's frame step: the median spacing of its distinct time centers converted to seconds (÷ r\_m), when it has at least two distinct time centers and that median, in seconds, lies within \[1/480 s, T\_τ/r\_m\]; else the checkpoint's Δt\_f·T\_τ/r\_m when it comes from a checkpoint; else 1/30 s (D-32).

**Per-instance time** \[+\]. Each instance has an offset o\_m (seconds, set by dragging its bar in the scene panel or typing a value) and an end rule, hold (default) or extrapolate (E9). Instances therefore align on the shared clock: two captures of the same event start together at o\_m = 0, or are shifted against each other. An instance evaluated outside its span shows an "extrapolating" badge and the time readout in italics. A single-timestamp instance shows no time controls.

**Audio** \[R: sound; §1.10\]. An instance with a soundtrack plays it so that soundtrack time 0 is τ₀,m: audio position = (τ\_m − τ₀,m)/r\_m seconds. Audio plays at speed 1 forward only; at any other speed, in reverse, while scrubbing and while paused it is silent, and it seeks to the clock's position when playback at speed 1 resumes (D-22).

**Cost.** τ\_m changes every frame while playing, so the active set and the sort are recomputed every frame (§1.4); the temporal index keeps the cull dispatch proportional to the active set (E3). While paused with a still view the frame redraws without preparing (§1.4).

### 1.7 Desktop interaction

**Window.** One resizable window, fullscreen on F11, vertical sync on by default, DPI-aware UI. The render scale of the quality tier applies to the splat layer only; the UI renders at the window's resolution.

**Cameras** \[R: keyboard and mouse\]. Two camera modes, toggled with O:

- *Fly* (default): W, A, S, D move forward, left, back, right in the camera's horizontal frame; E and Q move up and down; Shift multiplies the speed by 4 and Ctrl by 0.25; the mouse looks while the right button is held (the cursor is captured for the hold and released after it, so the UI stays usable); the wheel adjusts the base speed (0.1–20 m/s, 2 m/s by default, logarithmic steps).
- *Orbit*: the camera orbits the selected instance's box center (E10's B\_m), or the stage origin when nothing is selected; the left button drags the orbit, the middle button pans, the wheel zooms (distance 0.1–100 m).

Both modes share the vertical field of view (40°–110°, 60° by default), the engine's near and far planes for the other geometry (0.01 m and 1000 m; the primitives' culls are E6's), "frame selected" (F: the camera moves to see B\_m whole from its current direction), "reset view" (Home: 1.6 m above the origin, 2 m back, looking at the origin) and nine bookmarks (Ctrl+1 … Ctrl+9 save the camera, Alt+1 … Alt+9 recall it; bookmarks belong to the scene file).

**Selection and manipulation** \[R: move, resize, save and reset pose\]. A left click selects the instance E10's mouse ray hits (the ray through the cursor on the camera's image plane); Esc deselects; a double click frames the instance. The selected instance shows a gizmo with translate, rotate and scale handles (G, R and T choose the handle set; the handles follow the usual conventions: axis arrows, rotation rings, a uniform-scale cube) and the Scene panel shows its pose as editable numbers (translation in metres, rotation as yaw, pitch, roll in degrees, scale as a factor). Arrow keys nudge the selected instance by 1 cm in the ground plane (10 cm with Shift), PageUp and PageDown along y; \[ and \] turn it by 5° about y. Ctrl+F fits it (§1.5), Ctrl+P saves its pose, Ctrl+Backspace resets it, Delete unloads it after confirmation. Dropping model files on the window loads them; Ctrl+O opens the file dialog.

**Panels** \[D-21\]. A dock on the left with the tabs Library (sources, entries, load and refresh, filters by kind and name), Scene (instances with visibility, mode, pose, time offset, end rule, color transform, audio; save and load scene), Playback (the controls of §1.6), Display (render mode, centers radius and colormap, overlays, background, quality tier and the governor, render scale), Environment (desktop: background and grid only), Settings (§1.11) and Help (shortcuts, version, licenses; opened once on the first run). A bar above the viewport holds the play controls and the time readout. F1 opens Help, F2 hides and shows the whole UI, F3 the HUD (§1.13). The dock can be collapsed; its width is remembered.

**Screenshots** \[+\]. F12 writes a PNG of the viewport at its resolution to `<pictures dir>/openftgs-xr/<date>-<time>.png`, with a text chunk naming the player's version, the loaded models' identities, their poses, the clock time and the camera; the HUD and the UI are excluded.

**Training cameras and requests** \[+\]. When a `ftgs-scene` manifest sits beside a model (the same directory, any `*.json` whose `format` is `ftgs-scene`) or an index entry names one, the Scene panel offers its cameras: frustums drawn in the instance's frame (toggle), "jump to camera" (the fly camera takes the camera's pose and field of view, the clock the image's timestamp) and the camera list filtered by split. A `ftgs-render-request` file opened from the Library panel is replayed item by item the same way, for visual comparison with openftgs's renders of it; the numeric comparison is the headless command's.

**Command line** \[+; O: openftgs CLI exit codes\]. The binary is `ftgsxr` (D-36):

```
ftgsxr play [MODEL|URL|SCENE ...] [--tier TIER] [--xr] [--settings FILE] [--log-level LEVEL]
ftgsxr render MODEL REQUEST.json OUT.safetensors [--tier TIER]
ftgsxr info [--json]
ftgsxr validate MODEL ...
ftgsxr import IF OUT
ftgsxr export MODEL OUT
ftgsxr bench NAME [--out BENCH.json] [--model MODEL]
```

`play` starts the player with the given models, URLs or scene file loaded (`--xr` runs the XR session on the system's OpenXR runtime, §1.1). `render` answers a `ftgs-render-request` headless, without a window: MODEL is any §1.2 input; the tier defaults to `conformance` (§1.12: float32 storage, the model's full degree, `Depth32`, per-view sort, C = N, occlusion off); the request's `time_unit` must equal the model's, else exit 2; each item renders at its timestamp from its camera (E6) with the request's background and SH degree (E7, §1.2), and the file is written as `ftgs-renders` with `rgb/<id>` as float32 \[H, W, 3\], unclamped, and `alpha/<id>` as float32 \[H, W, 1\], `producer` = `openftgs-xr <version> (<GPU adapter name>)` and `request_sha256` = the SHA-256 of the request file's bytes \[O: openftgs §2.2, openftgs `io.write_renders`\]. `info` prints the adapter reply of openftgs §3.3's contract (§2.1): `name` `openftgs-xr`, `version`, `query_kinds` `[]`, `rasterizer` {`name`: `openftgs-xr wgpu-blend`, `version`}, and `render_conventions` with openftgs's values except `transmittance_stop`: null, since E7 applies none (D-7). `validate` reads and validates each model and prints its header information, exit 2 on the first invalid file. `import` and `export` validate their input and write a `ftgs-if` file (a byte copy for a `ftgs-if` input; the activated exchange form for a checkpoint or a PLY), so openftgs's harness can run its L0 and L1 levels with openftgs-xr as implementation B. `bench` runs a §3.5 benchmark. Exit codes: 0 success; 2 invalid input or environment (a file that fails validation, a request whose unit differs, no GPU adapter, no OpenXR runtime for `--xr`); 3 a numerical failure (a non-finite render, which writes no file) \[O: openftgs §2.1 CLI\].

### 1.8 XR interaction

**Session and spaces** \[X: OpenXR 1.1; D-24\]. The XR build runs one OpenXR session with the stereo view configuration. The primary reference space is STAGE; when the runtime offers none, LOCAL\_FLOOR (XR\_EXT\_local\_floor) is used, then LOCAL with the floor assumed 1.5 m below the session's origin and a warning in the HUD. Stage space is the player's world (§1.14). A reference-space change event (the user recentered the headset) re-places the content group so the models keep their stage-space poses. "Recenter" in the player moves the content group so that the selected instance, or the scene's center, stands 1.5 m in front of the user at its saved height. The runtime's boundary is left to the runtime; the player draws no boundary of its own.

**Controllers** \[R: controller support; X: XR\_META\_touch\_controller\_plus; A: no localized haptics on Touch Plus\]. One action set, `player`, with the actions of Appendix D.2 and suggested bindings for `/interaction_profiles/meta/touch_controller_plus`, for `/interaction_profiles/oculus/touch_controller` (the same paths, for runtimes that expose the Touch Plus as the older profile) and for `/interaction_profiles/khr/simple_controller` (select and menu clicks, aim and grip poses: Monado's simulated controllers and any other runtime). Analog thresholds: `grab` begins when the squeeze value rises above 0.6 and ends when it falls below 0.4; `select` begins when the trigger value rises above 0.6 and ends below 0.4; sticks pass through E12's response curve. While a hand grabs, its stick's y axis is `push_pull` and its x axis does nothing. Haptic feedback is a short amplitude pulse on the hand that acted: 10 ms at 0.3 on hover enter, 20 ms at 0.6 at the start and the end of a grab, 15 ms at 0.5 on a snap turn and on a UI click (D-44). In VR mode the controllers are drawn as the player's own low-polygon meshes at the grip pose; in passthrough mode only the ray's origin dot is drawn, since the real controllers are visible.

**Hands** \[R: hand tracking; X: XR\_EXT\_hand\_tracking, XR\_FB\_hand\_tracking\_aim, XR\_META\_simultaneous\_hands\_and\_controllers, XR\_META\_hand\_tracking\_frequency\_hint; A: `com.oculus.permission.HAND_TRACKING`; D-25\]. With hand tracking available, each hand provides an aim pose and pinch strengths from the aim state and 26 joint poses. The index pinch is the hand's `select` and `grab` at once (strength ≥ 0.7 begins, < 0.4 ends): a pinch on a hovered instance selects and grabs it until release, a pinch on the panel clicks, a pinch on nothing deselects; the middle-finger pinch is `play_pause`; the runtime's system gesture (the aim state's MENU\_PRESSED flag) toggles the main panel; the aim pose is the ray. When both a controller and a hand are tracked for the same side, the device that last produced input owns that hand; the frequency hint asks for high-frequency tracking while hands are the active input. In VR mode the hands are drawn as capsules between the joints with the joint radii, in a neutral material; in passthrough mode they are not drawn (the real hands are visible, and the environment depth lets them occlude the content, §1.9).

**Rays, selection and grabbing** \[R: grab with a ray and move; two hands resize; E10, E11; D-42, D-43\]. Each active hand casts a ray from its aim pose, drawn as a thin line to the first hit, or 10 m long, with a dot at the hit point; hovering an instance highlights it (§1.4). `select` on a hovered instance selects it; `select` on nothing deselects. `grab` on a hovered instance starts a one-hand grab: the instance follows the hand (E11) until release; while grabbing, the same hand's stick pushes and pulls the instance along the ray at 0.5 m/s times the current distance in metres (so far models move faster). A `grab` by the second hand on the same instance turns the grab into a two-hand grab: the instance scales with the hands' distance, follows their midpoint and turns with their yaw (E11), with "keep upright" on by default (yaw only) and "free rotation" as an option; releasing either hand returns to a one-hand grab by the other. Grabbing a UI panel by its title bar moves it the same way (two hands resize it). "Snap to floor" and "fit" are quick actions on the wrist menu and the panel.

**Locomotion** \[R: move by walking; sticks move, strafe and turn; E12; D-17, D-44\]. Walking is natural: the tracked head moves in stage space. In VR mode the left stick moves the rig (E12: forward, back, strafe in the head's yaw frame at v\_max) and the right stick turns it, snap turn by default (45°, a flick of the stick past 0.7 with a return below 0.3 between flicks) or smooth turn (60°/s), always about the head. A teleport option \[+\] replaces the smooth move: holding the left stick forward shows an arc to the floor, releasing teleports the rig there and fades the view for 150 ms. In passthrough mode stick locomotion is off: the real room cannot move, so the sticks keep only their other roles (push and pull while grabbing, scrolling the panel), the user walks, and the recenter and fit actions bring the content to them (owner decision, 2026-10-29, D-17). Comfort options: a vignette during smooth motion (on by default), a height offset of ±0.5 m for seated use, a reduced-motion setting that removes the animated transitions.

**User interface** \[R: easy to use AR/XR UI; D-21\]. Two surfaces:

- The *main panel*: the desktop's tabs (§1.7) without the mouse-only items, plus Environment (§1.9) and Comfort (the settings above), rendered to a 1024 × 768 texture on a quad 0.56 m × 0.42 m (resizable 0.3–1.2 m wide by a two-hand grab, the texture resolution following the width), world-locked, and movable by its title bar. The menu button, the system gesture or the wrist menu's panel button summon it: it appears 1 m in front of the head, 0.2 m below eye height, facing the user, and stays where it is until summoned again; summoning while it is visible hides it. Interaction: the ray's hit point on the quad is the pointer; `select` clicks, holding `select` drags (sliders, scroll bars); the pointing hand's stick scrolls the focused list. Touch targets are at least 1.2 cm at the default size (22 px at 1024 × 768), text at least 24 px, one Back button at the top of every sub-page, no hover tooltips, and a toast line at the bottom for messages (errors, "pose saved", "extrapolating").
- The *wrist menu*: five large buttons on a small panel attached to the left hand's grip pose (the right hand's in left-handed mode), 8 cm above the wrist, visible when the palm faces the user: play or pause, passthrough on or off, main panel, reset pose of the selected instance, fit the selected instance. It uses the same pointer.

The desktop's keyboard-free actions are reachable from these two surfaces; nothing needs a controller button to be discovered. Appendix D.2 and D.3 give the bindings.

**Comfort and accessibility** \[+\]. Left-handed mode swaps the two sticks' roles (`move` on the right stick, `turn` on the left) and the wrist menu's hand, while the face buttons keep their sides; UI scale from 0.8 to 1.5; the turn mode, vignette and seated options above; every sound can be muted (§1.10); the ray and highlight colors have a high-contrast alternative.

### 1.9 Passthrough and environment

**Environment modes** \[R: passthrough enabled or disabled; X: XR\_FB\_passthrough; A: `com.oculus.feature.PASSTHROUGH`; D-14\]. Two modes, switched from the Environment tab or the wrist menu and remembered in the settings:

- *VR mode*: the projection layer alone, opaque, with §1.4's background (a solid color and the optional floor grid).
- *Passthrough mode*: a passthrough layer (XR\_FB\_passthrough, reconstruction purpose) submitted before the projection layer, the projection layer flagged to blend with its texture's alpha, its contents premultiplied (E7, §1.4 resolve). The environment blend mode stays OPAQUE, as Meta documents for its runtime; ALPHA\_BLEND, which the runtime also lists, is not relied on (D-14).

The passthrough's appearance has three controls, brightness, contrast and saturation in \[−1, 1\], applied through the passthrough style's color map \[X: XR\_FB\_passthrough\] \[+\]; they are the "match the room to the model" direction and persist in the settings. On the desktop the Environment tab shows the VR-mode controls only and reports passthrough as unavailable.

**Depth occlusion** \[R: passthrough with occlusion using depth; X: XR\_META\_environment\_depth; A: Quest 3 and 3S only, `com.oculus.permission.USE_SCENE`; D-16, D-45\]. In passthrough mode, "occlusion" starts one environment-depth provider (created once per session, started when occlusion turns on and stopped when it turns off, after the permission is granted on first use), acquires one depth image per frame between the frame's begin and end, and gives the renderer the depth textures, their poses and fields of view and their near and far planes for E13. Soft occlusion is the default with δ = 5 cm (slider 0–20 cm); hard occlusion is an option. Hand removal (the provider's option) is off by default, so the user's real hands occlude the content they reach into; turning it on makes the content draw over the hands. The HUD shows the depth image's resolution and age. Where the runtime offers no environment depth (other headsets, the desktop) the control is absent.

**Light estimation and color matching** \[R: color matching using light estimation, and with depth estimation; A: Passthrough Camera API, Horizon OS v74 or later (v76 for Camera2), `horizonos.permission.HEADSET_CAMERA` and `android.permission.CAMERA`; E14; D-15, D-38\]. Four lighting modes for the content, in the Environment tab: off (default), manual (exposure in EV, white-balance temperature and tint sliders), auto global (E14 over the whole frame) and auto local (E14 over the pixels within the selected instance's depth band, which needs occlusion's depth provider). The auto modes open the headset's passthrough camera at its lowest resolution (1280 × 960) and 60 Hz after the permissions are granted on first use; the shim reduces each frame to a 64 × 48 RGB thumbnail with its timestamp and the camera's pose and field of view, and the player computes E14's statistics from the thumbnail, globally or over the depth band (D-15, §2.5). Enabling an auto mode captures the reference E\_ref from the next smoothed estimate; "re-capture reference" is a button; the current gains are shown, and the strength γ is a slider (0–1, 0.5 by default). The transform applies to every instance, or to the selected one when "per instance" is set, and is saved with the scene. Where the camera API is unavailable (an older OS, a denied permission, the desktop) only manual mode is offered and the UI says why.

**Floor, shadows and anchors** \[+; X: XR\_FB\_spatial\_entity, XR\_META\_spatial\_entity\_persistence; A: `com.oculus.permission.USE_ANCHOR_API`; D-26\]. The floor is stage space's y = 0 (§1.8). In passthrough mode each instance may cast a contact shadow: a soft dark disc on the floor under B\_m's footprint (opacity 0.3, feathered over 10 cm), on by default, which grounds the model visually without lighting. When a scene is saved in passthrough mode on the headset, a spatial anchor is created at the content group's origin and persisted; the scene file keeps its UUID (§1.11). Loading the scene locates the anchor and places the content group on it, so the models return to the same place in the room; when the anchor cannot be located (another headset, a forgotten anchor) the file's rig-relative pose is used and a toast says so. Anchors are forgotten when their scene file is deleted from the player.

### 1.10 Audio

**Sounds and volumes** \[R: sound on and off, volume; D-22\]. The player has a master mute ("sound") and three volumes in \[0, 100\] %: master, UI and soundtrack, in the Settings tab and the wrist menu's panel. UI sounds are short synthesized clips shipped with the player (the player's own assets, CC0): hover (a soft tick), select, grab start and end, snap turn, UI click, error (two tones) and confirmation ("pose saved"). Each sound can be turned off individually.

**Soundtracks** \[+\]. An instance plays a soundtrack when one is found: a file with the model's stem and the extension `.ogg`, `.wav`, `.flac` or `.mp3` beside the model (local sources), the index entry's `audio` for HTTP sources (downloaded with the model), or the `audio` field of the scene file. Synchronization follows §1.6: soundtrack time 0 is τ₀,m, audio plays at speed 1 forward and is silent otherwise. On the headset the soundtrack is spatialized at B\_m's center (volume and panning, attenuation 1/d beyond 1 m) when "spatial" is on, else stereo; the desktop plays stereo. Several instances with soundtracks play together.

**Output.** The system's audio output; the player records nothing and opens no microphone.

### 1.11 Settings and the player's own files

**Locations** \[D-23\]. The desktop follows the XDG base directories: settings, the pose store and scenes under `$XDG_CONFIG_HOME/openftgs-xr/` (`settings.toml`, `poses.json`, `scenes/`), the HTTP cache, thumbnails and logs under `$XDG_CACHE_HOME/openftgs-xr/` (`http/`, `thumbnails/`, `logs/`), the default model directory `$XDG_DATA_HOME/openftgs-xr/models/`, screenshots under `$XDG_PICTURES_DIR/openftgs-xr/`. The Quest keeps settings, the pose store and scenes in the app's internal files directory, the models and screenshots in the app-external files directory `Android/data/<application id>/files/` (`models/`, `screenshots/`, reachable over adb and MTP), and the HTTP cache, thumbnails and logs in the app's cache directory. Every file the player writes is written to a temporary sibling and renamed over the target, so a crash leaves the old file intact.

**Versioning rule** \[O: openftgs §2.2\]. Every file the player owns carries `format` and `version`; a reader rejects a major version it does not know, ignores a minor version, and ignores unknown keys. A settings file of an unknown major version is set aside as `settings.toml.unknown-<date>` and replaced by the defaults, with a warning in the HUD and the log.

**`settings.toml`** (`ftgsxr-settings` v1; saved at most once a second after a change and at exit) holds these tables, each key with the default §1 gives: `[general]` (`tier`, `governor`, `ui_scale`, `log_level`); `[[sources]]` (`kind` ∈ {`dir`, `http`, `documents`}, `location`, `name`, `flavor` for HTTP listings: `auto`, `index`, `nginx-json`, `html`); `[playback]` (`speed`, `loop`); `[display]` (`mode`, `centers_radius`, `colormap`, `background`, `grid`, `overlays`); `[environment]` (`mode`, `passthrough_brightness`, `passthrough_contrast`, `passthrough_saturation`, `occlusion`, `occlusion_soft`, `occlusion_delta_m`, `hand_removal`, `lighting_mode`, `lighting_manual` (`exposure_ev`, `temperature`, `tint`), `lighting_gamma`, `lighting_reference`, `contact_shadows`); `[locomotion]` (`speed_mps`, `snap_turn`, `snap_deg`, `smooth_dps`, `vignette`, `teleport`, `height_offset_m`, `left_handed`, `reduced_motion`); `[audio]` (`muted`, `master`, `ui`, `soundtrack`, `spatial`, per-sound switches); `[desktop]` (`fov_deg`, `fly_speed_mps`, `keys` as a table of action = key); `[xr]` (`refresh_rate`, `foveation`, `render_scale`, `reference_space`); `[cache]` (`max_bytes`, default 20 GiB). A missing key takes its default; a key of the wrong type is reported and takes its default.

**`poses.json`** (`ftgsxr-poses` v1): an object mapping each model identity (64 lowercase hex digits) to `{"translation": [x, y, z], "rotation": [x, y, z, w], "scale": s, "preset": "y-up" | "z-up" | "neg-y-up" | "custom", "fit_size_m": L, "saved_at": "<RFC 3339>"}`.

**Scene files** (`ftgsxr-scene` v1, `scenes/<name>.ftgsxr-scene.json`): `models`, an array of `{"source": {"kind", "location"}, "identity", "name", "pose": {translation, rotation, scale}, "visible", "mode", "time_offset_s", "end_rule", "lighting": {"exposure_ev", "temperature", "tint"} | null, "audio": <path or URL> | null}`; `clock`: `{"t", "speed", "loop", "range": [a, b] | null}`; `environment`: the `[environment]` keys above plus `background` and `lighting_reference` (E14's E\_ref as four numbers); `anchor`: `{"uuid"}` or null; `rig`: `{"pose"}` for XR and `camera`: `{"pose", "fov_deg", "mode"}` for the desktop; `bookmarks`: up to nine cameras. Paths under the model directory are stored relative to it, others absolute or as URLs.

**`index.json`** (`ftgsxr-index` v1, served by the user's HTTP server): `{"format": "ftgsxr-index", "version": 1, "entries": [{"name", "path", "kind": "ftgs-if" | "ftgs-checkpoint" | "ply", "size", "sha256"?, "thumbnail"?, "audio"?, "scene"?}]}`, every path relative to the index's URL. `kind` `ftgs-checkpoint` points at the directory, whose `manifest.json` and `params.safetensors` are fetched.

**Cache entries**: `http/<sha256 of the URL>/file` and `meta.json` (`url`, `etag`, `last_modified`, `size`, `sha256`, `fetched_at`); `thumbnails/<identity>.png` (256 × 256); `logs/ftgsxr.log` rotated at 10 MB, five files kept. The cache is pruned to `max_bytes` by least recent use, never removing a loaded model's file.

### 1.12 Performance budgets and quality tiers

**Quality tiers** \[D-37, D-12\]. A tier is one record of every number that changes outputs or speed; the governor (E16) adjusts a copy of the active tier's render scale, foveation, SH cap and sort mode, never its storage or capacity (those need a reload).

| Tier | Half-precision fields | SH cap | Sort key | Sort mode | Capacity C | Occlusion | Render scale | Foveation | Use |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `conformance` | none | the model's L | `Depth32` | per view | the loaded models' total N | off | 1.0 | — | `ftgsxr render`, R-n |
| `desktop` | none | 3 | `Depth32` | per view | 4,000,000 | off | 1.0 | — | default on the desktop |
| `quest-high` | velocity, scale, rotation, opacity, sh | 3 | `Depth32` | shared center | 1,500,000 | on | 1.0 | low | |
| `quest-balanced` | as above | 2 | `Depth32` | shared center | 1,000,000 | on | 1.0 | medium | default on the Quest |
| `quest-low` | as above | 1 | `Depth16` | shared center | 600,000 | on | 0.8 | high | |

Position, the rebased time center and the duration are always float32 (a half-precision duration in raw units could overflow). `quest-low` also stores the shared-center records' Σ^S in half precision (48-byte records, §1.4), the tier's `half_records` flag; the other tiers do not. The capacities are calibrated: set once from the first measurements of B-2 and B-3 on the reference hardware, then frozen; changing them needs a logged reason (Appendix B).

**Memory** \[D-13\]. Static GPU bytes per primitive: float32 storage 64 + 12 (L+1)², that is 76, 112, 172 and 256 bytes for L = 0 … 3; half-precision storage 42 + 6 (L+1)² (the duration stays float32), that is 48, 66, 96 and 138 bytes. Frame buffers per view (shared-center mode: once): records 48 C bytes (64 C in shared-center mode, 48 C with half-precision Σ in `quest-low`), sort keys and payloads 16 C, histograms about C, arguments and statistics under 1 KiB; the layer 8 bytes per pixel per view. Examples: a 1.5 M-primitive degree-2 model in `quest-high` takes 144 MB static plus about 122 MB of frame buffers for C = 1.5 M and about 47 MB for two eye layers at the default eye-buffer size; a 3 M-primitive degree-3 model in `desktop` takes 768 MB static plus about 260 MB of frame buffers for C = 4 M. The memory budget of a tier is 1.5 GiB of model buffers on the Quest and 75 % of the adapter's reported memory on the desktop; a load that would exceed it is refused (§1.2).

**Frame-time budgets** (calibrated by §3.5; the reference hardware of §1.1):

| ID | Budget |
| --- | --- |
| P-1 | Quest 3, `quest-balanced`, a trained `kitchen`-size model (1 M primitives at degree 2) in passthrough mode with occlusion: GPU frame time ≤ 12.4 ms (72 Hz with 1.5 ms margin) at every τ, and ≤ 9.6 ms (90 Hz) when the user selects 90 Hz |
| P-2 | Desktop, `desktop`, the same model at 1920 × 1080: ≥ 90 frames per second at every τ on the RTX 4090 |
| P-3 | Load time: ≤ 1 s per 100 MB of file from local storage (parse, validate, pack, upload), on both machines |
| P-4 | Sort: ≤ 2.5 ms for C = 1 M on the Quest, ≤ 0.4 ms on the RTX 4090 |
| P-5 | The frame loop never blocks on a GPU readback (§1.4 stage 8) |

**Half-precision bounds** \[D-12\]. Rounding a field to half precision changes it by at most 2⁻¹¹ relative (about 4.9 × 10⁻⁴) for velocity, scale, rotation and SH values of order 1, flushes scales below 6 × 10⁻⁸ world units, and rounds opacities near 1 to 1.0 (E7 clamps α at α\_max anyway). Each is below 1/255, so a half-precision tier passes R-n's tier bounds against the float32 tier (§3.2).

**Bounded deviations from openftgs's reference** \[D-7, D-35\]: the transmittance stop at 10⁻⁴ is not applied (E7 states the bound: up to the pixel's remaining transmittance, at most 0.1, where a near-opaque primitive arrives at a nearly covered pixel; below 10⁻⁴ elsewhere); accumulation in 16-bit floats (about 5 × 10⁻⁴ relative); the order of primitives at equal depth keys; float32 operation order. The rules that match exactly by construction: the pixel box with the opacity-aware extent and its cap, the Jacobian clamp, Σ′ + ε I, the determinant guard, the negative-form guard, the α skip, α\_max, the pixel centers, the near and far culls and the σ\_eff cull.

**Headset display** \[X: XR\_FB\_display\_refresh\_rate, XR\_FB\_foveation, XR\_META\_recommended\_layer\_resolution; A: Quest 3 rates 72, 80, 90, 96, 100, 120 Hz, default 72; default eye buffer 1680 × 1760; D-27\]. The refresh rate is selectable among the runtime's list (default: the runtime's); the swapchain size is the runtime's recommended size times the render scale, re-created when the scale changes by 0.1 or more; fixed foveation uses the runtime's levels (off, low, medium, high, dynamic allowed); Application SpaceWarp is not used (it needs motion vectors the splats do not produce).

### 1.13 Diagnostics

**HUD** \[+\]. Toggled with F3 or from the panel; drawn as a small overlay on the desktop and as a head-locked strip below the main panel in XR. It shows: frames per second and the display's refresh rate; CPU and GPU frame times (GPU from timestamp queries around the pipeline's stages; on the Quest also the runtime's metrics through XR\_META\_performance\_metrics when present); the loaded, active and visible primitive counts against C, with an overflow warning; the sort and cull times; GPU memory used against the budget; the clock T and each instance's τ\_m with its badges; the tier and the governor's current knobs; in XR, the tracking state of the head and hands, the depth image's resolution and age, the light estimate's gains, and the anchor state.

**Logs.** Structured logging with the levels error, warn, info, debug, trace (`--log-level`, default info): on the desktop to standard error and to the rotated log file of §1.11; on Android to logcat under the tag `ftgsxr`. Per-frame messages are rate-limited to one per second per site. Logs never contain a model file's contents, only identities, names, counts and timings. A warning is logged, and a toast shown, for every condition §1.15 lists as recoverable.

**GPU validation.** Debug builds enable the graphics API's validation layers and the shader validator; release builds do not. A validation error in a debug run of the test suite is a test failure (R-n).

### 1.14 Conventions

- **Frames.** Model space is openftgs's world: right-handed, no up axis assumed, units of the camera poses \[O: openftgs §1.4\]. Stage space is the player's world: right-handed, y up, metres, the ground at y = 0; on a headset it is the OpenXR STAGE space (or its fallback, §1.8); the engine's world frame is stage space. The pose P\_m maps model space into stage space (E5); the content group is a transform applied to every instance's pose, moved by recentering and by spatial anchors (§1.8, §1.9). Cameras in openftgs's conventions (OpenCV axes, world-to-camera, continuous pixels) are built per view as E6 says; the OpenXR-to-OpenCV camera rotation is diag(1, −1, −1) applied to the transposed view rotation.
- **Quaternions.** Files hold (w, x, y, z) \[O: openftgs §1.1\]; the engine's quaternion type stores (x, y, z, w); the conversion happens once, at load, and poses in the player's files are written (x, y, z, w) (§1.11).
- **Time.** τ in the model's `time_unit`; T in seconds; E9 converts; displays follow §1.6.
- **Color.** The SH coefficients produce display-referred sRGB-encoded values: openftgs trains against 8-bit frames read without gamma conversion \[O: openftgs §1.4 Images\], and openftgs-synth's frames are 8-bit sRGB (Appendix A, row 10). Blending happens in that space (E7, D-6); the resolve pass decodes for the engine's linear pipeline; the light transform multiplies in linear light (E14).
- **Units in the interface.** Metres, seconds, degrees; radians and metres in code; percentages for volumes.
- **Identifiers.** Model identities are 64 lowercase hexadecimal digits (D-40); file names of the player's files are ASCII.
- **Determinism.** The same inputs give the same images except at equal depth keys and through float32 operation order; the sort is stable; nothing depends on the frame rate except the clock.

## 2. Package architecture

### 2.1 Workspace layout and public API

The workspace is one Cargo workspace with one `[workspace.dependencies]` table, where every version of §2.3 is pinned once (D-1). Crates depend only downward, in bands: platform entry points → XR → application → engine → foundation. Within a band a crate depends only on the crates before it, and within a crate a module only on the modules before it in the tables below, so dependencies run one way with no cycles (CLAUDE.md). Every library crate's `lib.rs` re-exports (`pub use`) exactly the items this section lists; every other item is `pub(crate)` or private.

### 2.4 Performance architecture

The targets are §1.12's budgets P-1 to P-5 on the reference hardware. Four rules apply to every hot path, as in openftgs §2.4:

1. **No host synchronization in the frame loop.** Counts and dispatch sizes stay on the GPU (indirect draws and dispatches, §1.4 stages 2–5; D-30 gives the fallback should the Quest's driver refuse them); statistics are read two frames late; uploads are chunked (≤ 64 MB per frame); loading, validation and packing run on the compute task pool, listings and downloads on the I/O task pool.
2. **Exact optimizations are always on**: skipping the prepare stages when nothing changed (§1.4), the temporal index (E3), frustum culling, half-extent quads. They change no pixel.
3. **Approximate optimizations live in tiers only** (D-37): half-precision storage, the SH cap, `Depth16`, shared-center sorting, the render scale, foveation. Each is bounded in §1.12 and tested in §3.2; the conformance tier turns every one of them off.
4. **Memory is checked before it is spent**: the static estimate against the tier's budget before upload (§1.2), the frame buffers sized once per tier and capacity, the layer sized from the swapchain or window.

**Where the time goes** (one frame, one view; measured by B-1 to B-4):

| Stage | Runs | Cost driver | Plan |
| --- | --- | --- | --- |
| prepare | per instance | nothing (microseconds) | CPU, uniform writes only |
| cull | per instance, per dispatch range | rows visited (the active superset) × E6 | the temporal index keeps rows visited near the active set; one thread per row; early exits in the order σ\_eff, near/far, frustum |
| size | once | — | one workgroup |
| sort | once per view (per-view) or once (shared) | visible rows × passes | 4 passes of 8 bits; `Depth16` halves them; shared-center halves the views |
| draw splats | per view | covered pixels × overdraw | half-extent quads from the opacity-aware extent; discard below 1/255; render scale |
| draw centers | per view | visible rows | cheap; no sort |
| resolve | per view | pixels | one full-screen pass |
| statistics | once | — | copy to staging, mapped two frames later |

**GPU data layout.** Structure-of-arrays buffers per model (one buffer per field, no padding), float32 positions and rebased time centers, half-precision packs as `u32` pairs where the tier says so; the temporal index's permutation applied at pack time so dispatch ranges are contiguous. Records, keys, payloads, histograms and arguments in one `FrameBuffers` per tier and capacity, shared by every model of a view; two views in per-view mode hold two sets. The sort is the player's own classic radix sort (D-33): count, scan and scatter kernels with 256-thread workgroups, 8-bit digits, workgroup-local histograms and a single-workgroup scan of the global histogram, no subgroup operations and no decoupled look-back, so it runs on Adreno drivers as on desktop ones; keys and payloads ping-pong between two buffer pairs.

**Frame loop hooks.** On the headset the XR crate calls `xr_wait_frame` in its `XrFirst` schedule, begins the frame and acquires the swapchain images in the render world's `PreRender`, and releases them and ends the frame in `PostRender`; it renders one Bevy camera per eye into one array layer each \[L: bevy\_mod\_openxr 0.6.0 source\]. The player's two render nodes run inside each `SplatCamera`'s 3D pass: the prepare node before the opaque pass, the draw node after the opaque pass and before the transparent pass (so opaque geometry occludes splats by depth and the UI quad draws over them); the exact ordering labels are those of the pinned Bevy, where render passes are systems in the 3D schedule \[L: Bevy 0.19 migration guide\]. A render-world resource holds the frame's number and whether the shared prepare ran, reset at extraction, so the second eye only draws. The sort pose of shared-center mode comes from the two eye views extracted for the frame.

**Threads.** The main and render threads are Bevy's; loading uses the compute task pool (one task per load; validation and packing parallel over rows with rayon within the task), network the I/O pool (one download at a time, header reads in parallel), audio decoding the audio crate's thread. The shim's camera thread lives in the Android process (§2.5).

**The shim** (`android/app/src/main/kotlin/<application id>/MainActivity.kt` and `Shim.kt`) \[D-15, D-49\]. Rust reaches it through JNI (the `jni` crate, the JavaVM and activity handles from android-activity); Kotlin never calls into Rust: every result is polled. The surface is these static methods of `Shim`, and nothing else:

| Method | Does |
| --- | --- |
| `pickDocuments(requestId: Int, tree: Boolean)` | starts `ACTION_OPEN_DOCUMENT` (several files) or `ACTION_OPEN_DOCUMENT_TREE` and takes persistable read permission on the result |
| `pollPick(requestId: Int): Array<String>?` | the content URIs once the picker returns; null while pending; an empty array when cancelled |
| `listTree(treeUri: String): Array<String>` | the documents of a tree, one `name\tsize\tmime\turi` per entry |
| `openDocument(uri: String): Int` | a detached read-only file descriptor for the URI (−1 on failure) |
| `requestPermission(requestId: Int, permission: String)`; `pollPermission(requestId: Int): Int` | the runtime permission flow; −1 pending, 0 denied, 1 granted |
| `startCamera(): Int`; `pollCameraThumb(): FloatArray?`; `stopCamera()` | opens the passthrough camera through Camera2 at 1280 × 960 YUV, 60 Hz; each poll returns the newest 64 × 48 RGB thumbnail (9216 floats) followed by the timestamp and the camera pose and field of view when the metadata gives them, or null when none is new |

Rust wraps them as `QuestPlatform` (the `Platform`, `DocumentProvider` and `CameraFrames` ports of §2.1). The desktop's `LinuxPlatform` runs rfd's dialogs on a helper thread, grants every permission, and has no documents and no camera.

**Paths and storage** (§1.11): Android's internal files directory for settings, poses and scenes, the app-external files directory for models and screenshots, the cache directory for the HTTP cache, thumbnails and logs; all from android-activity's paths. Models may also come from `adb push` into the models directory (D-49).

**Desktop.** The system's OpenXR loader and runtime discovery (`XR_RUNTIME_JSON`, then the active-runtime file under the XDG config directories) through the openxr crate's `loaded` feature; `--xr` without a runtime is E-XR-RUNTIME. For development and the `xr` lane, Monado's `monado-service` with `QWERTY_ENABLE=1` or its simulated driver.

### 2.6 Coding standards

- Rust edition 2024; the workspace's `rust-version` is the pinned Bevy's minimum; `cargo fmt` with the default style; `cargo clippy --all-targets -D warnings`.
- `#![forbid(unsafe_code)]` in `ftgsxr-core`, `ftgsxr-io` and `ftgsxr-app`; `unsafe` only in `ftgsxr-render` (wgpu-hal interop, if any), `ftgsxr-xr` (OpenXR FFI the crates do not wrap) and `ftgsxr-quest` (JNI), each block with a `// SAFETY:` comment.
- `#![warn(missing_docs)]`; every `pub` item re-exported by `lib.rs` is one of §2.1's; a doc comment on each gives the spec items it implements.
- No `unwrap` or `expect` outside tests except on invariants, with the invariant in the `expect` message; errors are the typed enums of §2.1 and carry §1.15's codes.
- Markers: `// Q-n` for provisional decisions, `// D-n` where a decision's choice is coded; shaders carry the same comments; `# Q-n` in TOML and the Python tooling.
- Every source file starts with its SPDX header (CLAUDE.md); shaders are plain WGSL with a header comment naming the equations they implement; every constant of E6 and E7 reaches the shaders through the model's uniform block, never as a literal (D-39).
- Dependencies only from §2.3; `cargo deny check` passes.
- Logging through `tracing`; no `println!` outside the command-line output of §1.7.

### 2.7 Test infrastructure

**Lanes** (D-28). `cpu` tests run under plain `cargo test` on any machine. The other lanes are `#[ignore = "<lane>"]` with a name prefix: `gpu_` (needs a graphics adapter), `xr_` (needs an OpenXR runtime: Monado on the desktop), `dv_` (needs the Quest over adb), `net_` (needs the internet), `ds_` (needs `$OPENFTGS_DATASETS` and the trained tiny models). A lane runs with `cargo test -- --ignored <prefix>`, and the `gpu`, `xr` and `dv` lanes with `--test-threads 1`. The skills' ledger budgets every run (`.claude/skills/implement-without-subagents/SKILL.md`).

**Skeleton test.** `ftgsxr-core` has the always-run test `skeleton`: every source file of the workspace starts with its SPDX header; `cargo metadata` lists exactly §2.1's crates; every `.wgsl` file is referenced by `ftgsxr-render`.

**Organisation.** Unit tests in `#[cfg(test)]` modules beside the code (private helpers may have their own, `tdd` skill "Private tests"); spec tests at the public interface in `crates/<crate>/tests/`, named after the §3 row they pin (`u07_temporal_opacity_rebased`, `r03_probe_p3`); `ftgsxr-testkit` provides `fixtures_dir()`, `probe(name) -> (Model, RenderRequest)`, `reference_render(name) -> Vec<(String, RenderImage)>`, `metrics(a, b) -> Metrics { psnr, share, alpha }` (E15), `gpu_context() -> SplatDevice`, `random_model(seed, n, degree) -> Model`, `serve_fixtures() -> LocalServer` (an in-process HTTP server for the `cpu` lane's listing and download tests).

**Fixtures** (D-29). `tests/fixtures/` holds, committed: the probe models P1–P10 and the player's additional probes as `ftgs-if` files, their `ftgs-render-request` files, the reference renders (`ftgs render … --backend reference` output) as `ftgs-renders` files, a pre-posed merged model for the multi-model test, a tiny checkpoint (openftgs `ftgs train` for 20 iterations on the reference backend over a two-camera, two-frame synthetic scene with 64 primitives, a few hundred kilobytes) with its `ftgs export` file and a `write_ply` snapshot of it at τ₀, a `ftgs-scene` manifest of that synthetic scene, three listing bodies (an `index.json`, an nginx JSON listing, an Apache HTML listing), sample settings, scene and pose files of every version, `SHA256SUMS` over all of them, and `README.md` recording the openftgs commit, the commands and the adapter's `info` reply (`ftgs-adapter --backend reference info`; openftgs has no `ftgs info` command) that produced them. `tools/fixtures/make_probes.py` writes the probes and requests and runs openftgs; `tools/fixtures/merge_posed.py` writes the merged model; both are Python dev tooling that imports nothing from this workspace. Trained models are not committed: `tools/fixtures/train_tiny.sh` runs openftgs on openftgs-synth's `tiny` and `tiny_unsync` scenes (and `kitchen` for the budgets) into `$OPENFTGS_DATASETS/xr-fixtures/`, which the `ds` lane reads. A fixture's checksum mismatch fails the suite before any test.

**Continuous integration.** On every push: `cargo fmt --check`, `cargo clippy`, `cargo deny check`, the `cpu` lane, the skeleton test, and a Quest build (`cargo ndk` with the Android NDK, without Gradle) to catch compile breaks. The `gpu` lane runs on the owner's machine through the ledger before a merge; the `xr` lane there under Monado; the `dv` lane by hand with the headset connected; `net` and `ds` on demand.

## 3. Test plan

Six classes of tests pin the specification, each with a numeric pass criterion: unit tests U-n on the CPU, render conformance tests R-n on a GPU, integration tests I-n of the application (headless on the CPU, and on Monado for the XR ones), device tests Dv-n on the Quest 3, benchmarks B-n, and acceptance checks A-n a person performs on the headset. Each test is written from its row, through the public interface of §2.1, and its expected values come from a literal worked by hand, a property the row states, or an independent oracle the row names (`tdd` skill). A threshold marked "calibrated" is set once from analytic expectations or the first run on the reference hardware (§1.1), then frozen; changing it needs a logged reason. The lanes are §2.7's: U-n and the CPU I-n run under `cargo test`; R-n in the `gpu` lane; the XR I-n in the `xr` lane; Dv-n in the `dv` lane; the trained-model rows in the `ds` lane; the network rows of U-n use the in-process server and need no network.

### E.2 Horizon OS and Android

- The Khronos OpenXR loader for Android, version 1.0.34 or later, from Maven with prefab; the newer loader crashes on OS versions before v62 (Appendix A, row 22).
- Manifest: `com.oculus.intent.category.VR`; `android.hardware.vr.headtracking` required, version 1; `com.oculus.supportedDevices` (`quest3|quest3s` here); landscape; 64-bit only; `com.oculus.feature.PASSTHROUGH` for passthrough; `oculus.software.handtracking` with `com.oculus.permission.HAND_TRACKING` and `com.oculus.handtracking.frequency` for hands; `com.oculus.permission.USE_SCENE` for the Depth API and scene data; `com.oculus.permission.USE_ANCHOR_API` for anchors; `horizonos.permission.HEADSET_CAMERA` and `android.permission.CAMERA` for the passthrough camera (store apps need review for HEADSET\_CAMERA); minSdk and targetSdk 32 on the manifest page, targetSdk 34 for apps created after 2026-03-01; GameActivity needs API 31 or later.
- Depth API: public since SDK v60; Quest 3 and 3S; passthrough must be on; one provider per app, started and stopped, one acquire per frame between the frame's begin and end; depth images carry a pose, a field of view, nearZ and farZ, infinite far when farZ < nearZ; a minimum range of about 0.2 m and limited accuracy beyond 4 m; optional hand removal.
- Passthrough Camera API: Quest 3 and 3S, Horizon OS v74 or later (Camera2 on v76 or later); resolutions 1280 × 960, 1280 × 1280 and 1728 × 1728; 60 Hz; 20–40 ms latency; YUV420; the documented path is Camera2 from Kotlin; metadata gives the camera's source and position; a native Camera2 path is not documented.
- Display: 2064 × 2208 per eye, the default eye buffer 1680 × 1760 at render scale 1; refresh rates 72 (default), 80, 90, 96, 100 and 120 Hz; 8 GB of memory; CPU and GPU level trading.
- Sideloading: developer mode, `adb install`, the app under Unknown Sources, an MTP toggle; app-scoped storage recommended; broad storage permissions need store review.
- Android's document picker returns content URIs to an Activity callback and grants persistable read permission; it needs no storage permission.
