## 1. Context

- openftgs-xr is a player for the 4D Gaussian models (FreeTimeGS) that openftgs trains. The spec `docs/spec/openftgs-xr-spec.md` is the source of truth and is still a skeleton (revision 0: §0 notation only). `docs/prd/milestones.md` stays empty until the spec exists, so nothing can be built before this work.
- The owner's request (pasted list of 2026-10-29): two apps from one codebase, a Linux desktop player (keyboard + mouse) and a Meta Quest 3 OpenXR app (Touch Plus controllers, hand tracking, passthrough AR), with a feature list to extend "as much as possible" while staying easy to use and fast. Constraints: mainly Rust, Bevy and OpenXR (bevy.org, bevyengine/bevy, awtterpip/bevy_oxr). The models are generated by openftgs, so the player's input is openftgs's stable file interfaces (openftgs §2.2), chiefly the exchange model `ftgs-if`.
- Conflict found: CLAUDE.md, README.md, docs/GLOSSARY.md, the spec skeleton (§0 first sentence) and the skills' house rules all say "Apache-2.0 Python package" (`openftgsxr`, `__all__`, `PYTHONPATH`, pytest markers). The owner decided the switch (section 2). The spec cannot be written under Python rules, so the Rust switch comes first.
- What the openftgs spec fixes for us (read in full this session; line numbers in `docs/spec/openftgs-spec.md`): the model and its equations E1–E6 (64–169), time conventions (359–370), camera and world conventions (372–380), the file interfaces (844–934: `ftgs-if` 900–919, render request/renders 921–934, checkpoint 885–898), the temporal index rule (1034–1036), the harness adapter contract and L1 tiers (1195–1221), and the document conventions to mirror (E-n blocks, D-n table in Appendix B, U-n/S-n/B-n tables, Appendix A). What it leaves open for a player (openftgs spec extraction report): `ftgs-if` carries no cameras, no up axis, no unit scale and no frame interval Δt_f; the SH constants and band order are "gsplat's"; the JSON key names inside `render_conventions` and the `ftgs-renders` metadata keys are not spelled out; single-timestamp models need a special case (σt ≡ 1); color space is the file's encoded values without gamma conversion; openftgs-xr renders compare with openftgs renders at the "different rasterizers" tier (PSNR ≥ 45 dB and ≤ 0.5% of pixels with |Δ| > 1/255).

## 5. The spec: structure and content

The spec mirrors the openftgs spec's conventions exactly (same heading hierarchy, `**En · Name** [tags]` equation blocks with a ```latex``` body and normative prose, Appendix B table `ID | Gap | Decision | Rationale | Alternatives | Detecting test`, §3 tables `ID | Target | Test | Pass criterion`, Appendix A table `# | Source | What was taken`). openftgs items are cited with the prefix (`openftgs E1`, `openftgs D-84`, `openftgs §2.2`); the xr spec's own items are `E1…`, `D-1…`, `U-1…` without prefix. Provenance tags: `[R: <feature>]` owner's request list, `[O: openftgs §x]` inherited convention, `[X: XR_…]` fixed by an OpenXR extension, `[A: <Horizon OS / Android doc>]` platform rule, `[L: source]` literature or practice, `[D-n]` decision. Every feature the owner listed carries `[R]`; every addition is tagged `[D-n]` or `[L]` so the owner can strike it.

### §1 Specification (the normative part)
- **§1.1 Scope and platforms.** Desktop Linux (Vulkan via wgpu, X11/Wayland via winit) and Quest 3 (Android arm64, Vulkan, OpenXR). The XR build also runs on Linux against any OpenXR runtime (Monado qwerty/simulated for development; no passthrough there). Non-goals: training, editing primitives, other headsets as targets (they may work via OpenXR but are not tested), Windows/macOS (untested, not forbidden).
- **§1.2 Input models.** `ftgs-if` v1 as openftgs §2.2 defines it, quoted by reference (tensor names, dtypes, shapes, units, metadata keys, single-timestamp rule, opacity clamp, w ≥ 0 quaternion). Validation rules the player applies (finite, shapes agree, duration > 0, opacity in (0,1), sh shape vs sh_degree, unknown major version rejected, unknown keys ignored). Load-time options: SH degree cap, f16 storage, temporal pre-sort by time_center, importance subsampling to a budget (D-c13). Secondary input `ftgs-checkpoint` (`params.safetensors` + `manifest.json`: apply openftgs §1.1 activations and E14 with τ₀, τ₁ from the manifest) (D-c08). Model identity = SHA-256 of the file (keys pose files and caches).
- **§1.3 Equations** (xr spec's own E-n, each citing the openftgs equation it restates in raw time units):
  - E1 motion in raw time: μx(τ) = position + velocity·(τ − time_center) [O: openftgs E1, E14].
  - E2 temporal opacity σt(τ) = exp(−½((τ − time_center)/duration)²); σ_eff = σt·opacity; single-timestamp models: σt ≡ 1 (D-c09) [O: openftgs E3, E4, D-70, D-71].
  - E3 temporal active set: primitive active at τ iff |τ − time_center| ≤ duration·√(2 ln(255·opacity)) (undefined, hence never active, when 255·opacity ≤ 1), widened by margin m (D-c10) [O: openftgs D-55, E6].
  - E4 color: real SH basis with the constants and band order written out in full (from openftgs `sh.py`/gsplat, Apache-2.0), +0.5 offset, clamp at 0, direction from the view's eye position to μx(τ) in model space (so the pose transform is applied to the eye, not to the primitives) [O: openftgs E2, D-4].
  - E5 covariance and pose: Σ = R(q) S Sᵀ R(q)ᵀ; the pose P_m scales positions, velocities and scales uniformly by s, rotates by q (quaternion (w,x,y,z) → glam (x,y,z,w) conversion stated) [O: openftgs E5].
  - E6 projection: per view, EWA Jacobian with the 0.15 clamp margin, Σ' + 0.3·I, conic, per-axis radii with the √(2 ln(255σ_eff)) extent capped at 3.33, culls (z near/far, det ≤ 0, off-screen); the OpenXR asymmetric-FOV projection expressed as K (fx, fy, cx, cy) so E6 is one formula for desktop, headless and XR [O: openftgs E6; X: XrFovf].
  - E7 compositing: front-to-back over the sort order, α = min(0.999, σ_eff·exp(−½ dᵀΣ'⁻¹d)), skip α < 1/255, premultiplied-alpha blending (hardware blend `one, one-minus-src-alpha`), background composited as image + (1 − α_acc)·c_bg (transparent in passthrough), early termination absent (hardware blending has none; note the ≤1e-4 transmittance difference as a documented deviation under the 45 dB tier) [O: openftgs E6, D-76].
  - E8 sort key: per view, 32-bit key from camera-space depth of μx(τ) (float bits with sign handling), far-to-near draw order; shared-eye-center variant (D-c04).
  - E9 playback clock: τ_m = τ₀,m + offset_m + speed_m·T, loop modes (loop, ping-pong, once, hold), range [τa, τb] ⊆ [τ₀, τ₁] with extrapolation allowed and flagged outside [O: openftgs §1.4 Time].
  - E10 ray selection: ray from the aim pose; hit test against the model's oriented bounding box at τ (box from positions over sampled τ, cached), then nearest primitive center within an angular cone for the hit point; hover distance.
  - E11 grab transforms: one-hand grab keeps the model's pose relative to the controller pose; two-hand: s' = s·|p_L' − p_R'|/|p_L − p_R|, rotation about the stage up axis from the hand-pair yaw (optional full rotation), translation of the midpoint; pivot = midpoint.
  - E12 locomotion: stick → velocity in the head-yaw frame (m/s, configurable), snap turn angle, smooth turn rate; in passthrough mode the same inputs move the content group instead (D-c17).
  - E13 depth occlusion: reproject fragment depth into the environment depth view (pose, FOV, nearZ/farZ from `XrEnvironmentDepthImageMETA`, infinite far when farZ < nearZ), occlusion weight w = smoothstep over (d_env − d_frag) with a tolerance in metres (hard mode: step) [X: XR_META_environment_depth].
  - E14 light estimate and color transform: global estimate from passthrough camera frames (mean luminance Y and mean chroma → exposure gain g and white-balance gains (r,g,b)); local estimate restricted to pixels whose environment depth lies within the model's depth band; applied as c' = clamp(diag(gains)·g·c) before compositing; manual sliders set the same gains; fallback when no camera access [A: Passthrough Camera API; D-c15].
  - E15 conformance metrics for R-n: PSNR after clamping both renders to [0,1], share of pixels with |Δ| > 1/255, alpha max difference [O: openftgs §3.3 L1].
  - E16 quality governor: frame-time error → ordered quality knobs (resolution scale, primitive budget, SH degree, FFR level, sort period) with hysteresis.
- **§1.4 Rendering.** Per-frame stages: (1) temporal slice + frustum cull + sort-key pass (compute, per model, per view), (2) stream compaction producing the visible count into the indirect-draw args (no CPU readback), (3) GPU radix sort of (key, index), (4) indirect instanced draw of quads in Bevy's transparent phase, premultiplied alpha, depth test on/write off, (5) centers mode: same buffers, screen-space discs of fixed pixel size, color = SH DC (or time/velocity/opacity colormaps). Multi-model ordering (D-c05). Stereo: two views, per-view sort by default (D-c04). Color space (D-c06). Depth output for later passes (UI, controllers). Render targets: Rgba16Float HDR on desktop optional, Rgba8UnormSrgb default; XR swapchain format from the runtime. MSAA off for the splat pass. Budgets and tiers (§1.12).
- **§1.5 Scene, library and sources.** Library entries (name, path/URL, size, N, sh_degree, time span, duration, producer, thumbnail), sources: local directories, HTTP index (own manifest `index.json`, nginx `autoindex_format json`, HTML autoindex parsing of `<a href>` links), direct URL, Quest app-external directory, SAF picker (shim); download cache with ETag/Last-Modified validation and Range resume; optional `SHA256SUMS`/`*.sha256` verification; load/unload/reload with progress and cancel; several models at once; per-model pose, visibility, label; pose persistence per model identity; default placement rule (bounding box centred 1.5 m ahead at eye-height-minus-box-half-height, bottom on the floor, with orientation presets Y-up/Z-up/−Y-up/custom since `ftgs-if` has no up axis, D-c11); scene files (models, poses, playback, environment) save/load; spatial anchors for scene placement across sessions (§1.9).
- **§1.6 Playback.** Clock, play/pause, scrub, speed (±, 0.1×–4×), loop modes, range, frame step (default step from the model: median spacing of distinct time centers, else 1/30 s), per-model offset/speed, sync group, audio sidecar (`<model>.ogg|.wav|.mp3` next to the file or named in `index.json`) seeking with the clock; sound on/off and volume [R].
- **§1.7 Desktop interaction.** Fly camera (WASD/QE, RMB look, speed modifiers), orbit camera around the selected model, FOV, bookmarks, reset view, transform gizmo and numeric pose fields, keyboard shortcut table (one table, normative), mouse selection, drag-and-drop file loading, panels (Library, Scene, Playback, Display, Environment, Settings, Help, Stats), screenshots (PNG with metadata), training-camera frustums and "jump to camera" when a `ftgs-scene` manifest sits beside the model, CLI of the binary `ftgsxr` (`ftgsxr play [MODEL|URL…] [--scene FILE] [--tier T] [--xr]`, `ftgsxr render MODEL REQUEST OUT` (headless, mirrors `ftgs render`), `ftgsxr info`, `ftgsxr import`/`export` (validate and copy, for openftgs's harness), `ftgsxr validate`, `ftgsxr bench`), exit codes mirroring openftgs (0, 2 invalid input, 3 numerical failure).
- **§1.8 XR interaction.** Reference spaces (STAGE primary, LOCAL_FLOOR then LOCAL fallback), recenter, boundary respect; controller binding table for `/interaction_profiles/meta/touch_controller_plus` (trigger select/ray-grab, squeeze grab, left stick move/strafe, right stick turn, X/A quick actions, Y/B play-pause and reset pose, menu button toggles the panel, haptics on hover/grab/snap; no localized haptics on Touch Plus); hands via XR_EXT_hand_tracking + XR_FB_hand_tracking_aim (aim pose, pinch select/grab, system gesture = menu), simultaneous hands and controllers; ray interaction (E10, E11), two-hand scale/rotate, snap-to-floor, keep-upright toggle; locomotion (E12) with comfort options (snap turn default 45°, vignette, teleport); UI: a grabbable world-locked main panel (UI rendered to a texture on a quad, pointer from the ray), a wrist/palm quick menu, large targets, one back action; sound feedback.
- **§1.9 Passthrough and environment.** Passthrough on/off (XR_FB_passthrough layer under the projection layer, projection layer with source alpha, premultiplied; blend mode OPAQUE per Meta docs, ALPHA_BLEND probed at runtime, D-c16); passthrough style controls (brightness/contrast/saturation, optional LUT ≤ 32) as the "match the room to the model" direction; depth occlusion (E13; hard/soft; hand removal toggle; USE_SCENE permission; Quest 3/3S only); light estimation (E14; off/global/local; Passthrough Camera API, permissions `horizonos.permission.HEADSET_CAMERA` + `android.permission.CAMERA`, OS v74+/v76+; manual fallback); floor and room (XR_FB_scene floor plane for placement; contact blob shadow); spatial anchors (XR_FB_spatial_entity + XR_META_spatial_entity_persistence; USE_ANCHOR_API) so a scene's placement survives sessions.
- **§1.10 Audio.** UI sounds (hover, select, grab, snap, error), soundtrack per model (E9-synced, seekable), master/UI/soundtrack volumes, mute, optional spatialization at the model's position.
- **§1.11 Settings and files the player owns.** Versioned formats (like openftgs §2.2): `settings.toml`, pose files (`poses/<sha256>.toml`), scene files (`*.ftgsxr-scene.json`), library manifest `index.json` (server side), download cache layout; locations per platform (XDG on Linux; app-external files dir on Quest); atomic writes; migration rule (unknown keys ignored, unknown major rejected).

- **§1.13 Diagnostics.** Perf HUD (frame time CPU/GPU, N_vis, sort time, memory, XR_META_performance_metrics on Quest), log files (`tracing`; logcat on Android), `--log-level`, crash-safe settings.

### §2 Package architecture (design in section 13; written out in full in the spec)
- **§2.1 Workspace and bands.** Cargo workspace with one `[workspace.dependencies]` pin table. Crates in import bands (each band imports only from the bands below; within a band only from earlier crates/modules): A Foundation `ftgsxr-core` (engine-free: types, SH, motion, covariance/projection mirror, temporal index, clock, pose, loader, GPU layout, openftgs request/renders formats) then `ftgsxr-io` (paths, settings, scene files, listing parsers, HTTP, model sources); B Engine `ftgsxr-render` (wgpu passes and WGSL shaders + the Bevy plugin adapter + the headless renderer); C Application `ftgsxr-app` (intents, platform port, library, playback, manipulation, rig/locomotion, UI, audio, capture, persistence, headless commands, desktop input); D XR `ftgsxr-xr` (session, tracking, XR intents, passthrough, depth, light, anchors, panel); E Platform `ftgsxr-desktop` (bin `ftgsxr`), `ftgsxr-quest` (cdylib + `android/` Gradle project with the Kotlin shim); dev-only `ftgsxr-testkit` and `tools/fixtures/` (Python driving openftgs). Module table `Crate/module | Responsibility | Spec items` and full Rust signatures with doc comments (shapes, units, D-n), in the style of openftgs §2.1; `lib.rs` re-exports are the public API.
- **§2.2 Files.** The player's own versioned formats (`settings.toml`, `ftgsxr-poses` v1, `ftgsxr-scene` v1 JSON, `ftgsxr-index` v1 JSON, cache layout) and the openftgs files it reads and writes (`ftgs-if`, `ftgs-checkpoint` read; `ftgs-render-request` read; `ftgs-renders` written).

### §3 Test plan
- **§3.1 Unit tests U-n (class `cpu`)**: loader (every validation rule, metadata parsing, f16 option round-trip, checkpoint activations), E1–E5 and E8–E12 numerics with hand-worked literals and property variants, SH basis against an independent evaluation from the published constants, pose composition, playback clock (loop modes, extrapolation flags, sync), active-set bound (E3) including 255·opacity ≤ 1, index/listing parsers (own manifest, nginx JSON, Apache HTML), cache validators (ETag, Range), settings/pose/scene file round-trips and version rules, binding table completeness, CLI exit codes.
- **§3.2 Render conformance R-n (class `gpu`)**: probe models P1–P10 analogues (static isotropic, moving, short duration, near-opaque, SH-only, near-plane crossing, depth-order swap, 1/255 boundary, partly off-screen, outside [τ₀, τ₁]) and the trained `tiny` models, rendered headless from `ftgs-render-request` files and compared with committed `ftgs render --backend reference` outputs at the different-rasterizers tier (E15); sort correctness (GPU sort vs CPU sort, per view); visible count vs CPU count; centers mode pixel positions; color-space check (a gamma mistake fails 45 dB).
- **§3.3 Integration I-n (class `xr` on Monado, `cpu` headless app)**: app boots headless, loads/unloads models, poses persist and reset, playback states, locomotion math with simulated input, UI panel interaction via the virtual pointer, HTTP source against a local test server (class `network` serves fixtures locally), XR session lifecycle and two-view rendering on Monado's simulated driver.
- **§3.4 Device tests Dv-n (class `device`, Quest 3 via adb)**: install, launch, session to RUNNING, frame rate ≥ 72 Hz on a budgeted model, passthrough layer present, depth provider start/stop, hand tracking joints, anchors persist across restarts, permissions flow, file picker shim round-trip, logcat free of Vulkan validation errors.
- **§3.5 Benchmarks B-n**: desktop render FPS vs N and SH degree; Quest frame time per tier (calibrated budgets); sort time vs N; load time vs size; memory per primitive per option; light-estimation cost.
- **§3.6 Acceptance checks A-n (manual, on the headset)**: comfort of locomotion defaults, UI reachability, grab precision, passthrough occlusion quality, color matching plausibility; each with a pass statement a human can judge.

## 12. Glossary and module docs (candidates for branch `docs-xr-terms`, in GLOSSARY-FORMAT shape; references filled with final numbers)

New area `### Player` (and reuse Representation, Time, Rendering, Files, Workflow where a term fits):
- **Model instance**: One loaded exchange model placed in the stage with its own pose, visibility, label and time offset; several instances may share a file. §1.5. _Avoid_: model (unqualified, where the file is meant), object, asset, splat cloud.
- **Pose**: A model instance's rigid placement in stage space plus a uniform scale, (t, q, s), saved per model identity. E5, §1.5. _Avoid_: transform (Bevy's component), placement, anchor (reserved for spatial anchors).
- **Stage space**: The player's world frame: OpenXR STAGE (or its fallback) on a headset, a Y-up metre frame with the ground at y = 0 on the desktop. §1.14. _Avoid_: world space (ambiguous with openftgs's world), room, tracking space.
- **Playback clock**: The player's single time source T, in seconds, from which every model instance's model time is derived. E9. _Avoid_: timeline, global time, animation time.
- **Model time τ_m**: The raw timestamp at which a model instance is evaluated, τ₀,m + offset + speed·T. E9. _Avoid_: current time, frame, t (openftgs's normalized time).
- **Active set**: The primitives whose effective opacity can reach 1/255 at the model time, the only ones that enter sorting and drawing. E3. _Avoid_: visible set (after frustum culling and radii), live set (training), bucket.
- **Splatting mode**: The render mode that draws every active primitive as its projected Gaussian footprint. §1.4. _Avoid_: splat view, Gaussian mode, full render.
- **Centers mode**: The render mode that draws each active primitive as a fixed-size disc at its moved position, colored by a colormap. §1.4. _Avoid_: point cloud mode, debug points, dots.
- **Sort key**: The per-view 32-bit integer derived from a primitive's camera-space depth that orders drawing far to near. E8. _Avoid_: depth key, z-order, distance.
- **View**: One eye's camera in XR, or the single camera on the desktop; sorting and projection are per view. E6, E8. _Avoid_: eye, camera (Bevy's component), viewport.
- **Content group**: Every model instance together, the thing stick locomotion moves in passthrough mode and recentering resets. E12, D-c17. _Avoid_: scene (the saved file), world, root.
- **Passthrough mode / VR mode**: The environment modes: the real room behind the content, or an opaque virtual background. §1.9. _Avoid_: AR mode, MR mode, immersive mode.
- **Environment depth**: The per-eye depth image the Depth API provides for occlusion. E13. _Avoid_: scene depth, real depth, depth map (ambiguous with our own depth output).
- **Light estimate**: The exposure and white-balance gains derived from passthrough camera statistics, global or depth-banded local. E14. _Avoid_: lighting, ambient light, color correction (the manual controls).
- **Model source**: A place the library lists models from: a local directory, an HTTP index, the Quest app directory or a picked file. §1.5. _Avoid_: repository, server, location, path.
- **Library**: The list of models available from every model source, with their metadata. §1.5. _Avoid_: catalog, browser, file list.
- **Scene file**: The player's saved set of model instances, poses, playback and environment settings. §1.11. _Avoid_: scene manifest (openftgs's `ftgs-scene`), project, save file.
- **Probe model**: A small hand-built exchange model committed as a fixture, each isolating one behavior like openftgs's probes P1–P10. §3.2. _Avoid_: test model, synthetic scene (openftgs S-n), sample.
- **Reference render**: An image rendered by openftgs's reference backend for a request, committed with its checksum, that conformance tests compare against. §3.2. _Avoid_: ground truth (the dataset's), golden image, baseline (reserved for benchmarks).
- **Quality tier**: A named set of values for the quality knobs (resolution scale, primitive budget, SH degree, FFR level, sort period). §1.12, E16. _Avoid_: preset, graphics setting, level.
- **Shim**: The minimal Kotlin code of the Android build that calls platform APIs with no native path and returns results to Rust over JNI. §2.5. _Avoid_: wrapper, bridge, Java layer, plugin.
- **Conformance test R-n / Integration test I-n / Device test Dv-n / Acceptance check A-n**: the §3 classes (Workflow area), each one sentence. §3.
- Conventions paragraph addition (not an entry): §2 identifiers keep their spelling in code even where the glossary avoids the word in prose; the render crate's `Splat*` types are the standing example.
Module docs: none until modules exist; the first PRD (M1) adds `docs/modules/<core crate>/` pages for the loader's validation order and the time conversions.

**Per-frame pipeline.** (1) CPU per model: τ_m, dispatch ranges from the index, uniform block (pose matrix, rotation, scale s so Σ_world = s²RΣRᵀ, τ_m − τ₀ as f32, SH degree, grade, mode). (2) `cull.wgsl` per model per range: σt, σ_eff (skipped for single-timestamp), early-out σ_eff < 1/255, μx(τ) → world → view, near/far, frustum with dilation margin, J clamp 0.15, Σ' + 0.3I, extent √(2 ln(255σ_eff)) ≤ 3.33, radii, det guard, SH color at the sort pose with grade; visible rows `atomicAdd` a slot in the record buffer and write (key, slot); centers-mode rows go to a second region. (3) Sizing pass writes dispatch args. (4) Radix sort (4 passes × 8 bits, or 2 for Depth16) by `dispatch_workgroups_indirect`, ping-pong. (5) `splat.wgsl`: one `draw_indirect` of 4-vertex strips into an Rgba16Float premultiplied layer cleared to 0, blend One/OneMinusSrcAlpha, depth test against the pass depth at the center depth, no depth write; fragment α = min(0.999, σ_eff·exp(−½dᵀΣ'⁻¹d)), discard < 1/255, optional occlusion attenuation. (6) `centers.wgsl`: opaque discs, depth write on. (7) `resolve.wgsl`: layer → linear view target as `over` (headless skips it and reads the layer back). (8) stats block copied to staging, mapped two frames later. Shared-center mode: records hold world-space data (position, Σ_world, color, key); each eye's vertex shader projects per vertex; a render-world `SplatFrameState` flag makes only the first eye prepare. Bevy attachment: `RenderAssetPlugin` for `SplatAsset`, `ExtractComponentPlugin` for the components; nodes in each `SplatCamera`'s Core3d graph: prepass before the opaque pass, draw after `MainOpaquePass` and before `MainTransparentPass` (controllers and hands occlude splats by depth; UI panels draw over them); MSAA off on splat cameras; node labels verified at the pinned Bevy (0.19 made render passes systems: verify the exact ordering API).

**Record layouts and memory.** Per-view record 48 B (μ' 8, conic 12, half-extents 8, color/α 4×f16 8, depth 4, flags 4); shared record 64 B (position 12, Σ_world 6×f32 24 (f16: 12), color/α 8, key 4, flags 4). Static SoA bytes per primitive: f32 fixed 64 + SH 12(L+1)² → 76/112/172/256 for L = 0..3; f16 option fixed 40 + 6(L+1)² → 46/64/94/136 (position and rebased time always f32). Per-frame: records 48C (per view) or 64C (shared), sort keys+payloads ping-pong 16C, histograms ≈ C, args/stats < 1 KiB; layers 8 B/pixel/eye. Examples: Quest N = 1.5M, L = 2, f16 → 141 MB static, C = 1M shared → ~81 MB frame buffers, two eye layers ≈ 50 MB; desktop N = 3M, L = 3, f32 → 768 MB static, C = N per-view → 192 MB. f16 bounds: ≈ 5e-4 relative on rotation/velocity/scale/SH, opacity near 1 saturates but α is clamped at 0.999 anyway; all below 1/255, pinned by R-n tier tests.

**What cannot match openftgs under hardware blending (bounded, in `info` and §3.2):** the 1e-4 transmittance stop (omitted terms ≤ 1e-4 per channel), Rgba16Float accumulation (≈ 5e-4 relative), tie order at identical depth keys, f32 operation order. **What matches by mirroring the rules:** pixel box ⌈e√Σ'ᵢᵢ⌉ with the opacity-aware e capped at 3.33, J clamp, Σ' + 0.3I, det ≤ 0 cull, negative-form guard, α skip 1/255, α_max 0.999, +0.5 pixel centers, near/far culls, σ_eff cull. Hence the L1 different-rasterizers tier is the conformance criterion and `project()` gets hand-worked U-n rows.

**Multi-model.** One global record buffer per view (all models append under one atomic counter), one sort, one indirect draw: correct interleaving of overlapping models; one shared capacity (overflow flagged; conformance tier sets C = ΣN). Rejected: per-model sort with model-distance ordering. Detecting test: two posed probes vs openftgs's render of the pre-posed merged file written by `tools/fixtures/merge_posed.py`.

**Headless conformance.** `ftgsxr render MODEL REQUEST OUT`: `open_model` → `read_request` → `HeadlessRenderer` with the conformance tier (f32, full SH, Depth32, per-view, C = ΣN, occlusion off) → per item `Camera::engine_view`/`intrinsics` feed the same `SplatPasses` (clip x = 2μ'ₓ/W − 1, y = 1 − 2μ'ᵧ/H; request `time_unit` must equal the model's, else exit 2) → readback → rgb = premul + (1 − α)·background unclamped, alpha = α → `write_renders` with producer `openftgs-xr <version> (<adapter>)` and the request SHA-256. `import`/`export` validate and copy bytes (native model = ftgs-if), so openftgs's harness L0 holds trivially and L1 can run with openftgs-xr as adapter B.

**Platform.** Android: `cargo ndk -t arm64-v8a` → Gradle project `android/` with the Khronos loader AAR from Maven (license read first; no build.rs download) and GameActivity (or a NativeActivity subclass if bevy_mod_openxr 0.6 forces the `native-activity` feature: android-activity backends are mutually exclusive across the graph); no Bevy window on Quest (PR #205); paths: settings/scenes internal, models/screenshots app-external (`/sdcard/Android/data/<pkg>/files/…`), HTTP cache in the cache dir. Linux: rfd, `directories` project dirs, the system OpenXR loader and active-runtime discovery.
